Anatomy of an LLM Agent; Planning and Reasoning

An agent is an LLM that reasons, remembers and uses tools, acting in a loop within an environment. Of those parts, planning and reasoning came first: chain-of-thought makes a model think before it answers, ReAct interleaves that thinking with actions and observations so reasoning stays grounded, and Reflexion has the agent write lessons from its own failures into memory for the next attempt.

2 · The skeleton of an agent ▶ 23:35

A conceptual framework, not a precise one: the arrows in the diagram "don't carry a lot of weight".

  • LLM core. Agents are built on LLMs, and stronger models generally mean better agents. Hence a live debate: should you train for agents, or improve the harness around the model?
  • Planning and reasoning. A big task must be decomposed into smaller pieces, perhaps each handled by a sub-agent; you may also add explicit mechanisms to improve reasoning.
  • Memory. When an agent works on a task for more than two hours, it must know what has happened so far and use that as context for reasoning.
  • Tools ▶ 24:34. Even a model that solves hard maths can't tell you where CS329Z meets today; give it retrieval and it can search the Stanford website (or an official weather database for today's weather). There was a time when GPT-4 was amazing yet couldn't multiply two 3-digit numbers. Tools let agents take factual and more consistent actions.
  • Actions. Tool calls, interactions, responses to users: all of these are agent actions.
  • Environment ▶ 25:58. The agent observes what happens in the environment and acts on it.

On top of one agent you can have several; and even within one agent, each box can be configured and optimised separately. That is why harness design and optimisation matter so much later in the course: everyone wants the best configuration of this diagram.

Same architecture, different labels ▶ 26:57. There has been lots of debate about what is or isn't an agent (no debates in this class). A 2023 diagram by an OpenAI researcher has tools, memory, planning and action; the cognitive architectures for language agents framework has memory with retrieval (to read) and learning (to write), reasoning, and so on. Different vocabulary, same picture:

An agent is an LLM that reasons, remembers and uses tools, and acts in a loop within its environment.
Going beyond the lecture. The two diagrams are very likely Lilian Weng's blog post "LLM Powered Autonomous Agents" (2023) and CoALA, "Cognitive Architectures for Language Agents" (Sumers, Yao, Narasimhan and Griffiths, 2023).

3 · What does "reasoning" mean? ▶ 28:01

The analogy with human reasoning is controversial (again, no debate here), but it helps to set three meanings side by side:

For…Reasoning means
HumansMental processes such as deduction, analogy and planning
LLMsUsually the chain of thought, which may not be faithful to what actually happens inside the model
AgentsInternal actions that update the agent's own state (as opposed to external actions on the environment)

Why reasoning helps an agent ▶ 29:33. At step $t$ the agent observes "you are cooking a dish and the salt is out"; its next action is "turn right". Why? The mapping from observations to actions is huge, which makes agents hard to audit and hard to improve. Add explicit reasoning: "the dish should be savoury; since salt is out I should find something equivalent; it is in the cabinet to my right", and the turn makes sense. Reasoning helps in two ways:

  • Generalisation: the same reasoning works in new, similar situations.
  • Alignment: you can see why the agent did what it did.

4 · ReAct vs plain prompting ▶ 31:13

A HotpotQA question about the Apple Remote. Standard prompting fails. Chain-of-thought fails too, and that is more dangerous: a convincing reasoning trace with a wrong answer. ReAct loops thought → action → observation:

  1. The question mentions the Apple Remote, so search for it to find what it was originally designed to interact with. That thought induces a search action, which returns the Wikipedia description.
  2. Reasoning extracts the key fact: it was designed for Front Row. Next thought: search Front Row to find what else controls it. But that page doesn't have the information.
  3. Reasoning recovers: search "Front Row (software)" instead. When the agent believes it has the answer, it finishes and returns it.

The reasoning traces induce and adjust actions; the actions bring in new knowledge that supports the reasoning. The trajectory is intuitive, interpretable and fairly factual. Step through both methods side by side:

Hallucination is a serious problem for CoT and many prompting techniques; ReAct's loop of reasoning plus actions mitigates it a lot.

Self-consistency (SC) ▶ 34:01, the "SC" on the results chart, is a simple trick on top of CoT: sample a diverse set of reasoning paths instead of one, then pick the most consistent final answer, a kind of majority vote.

5 · Reflexion: learning from verbal feedback ▶ 35:05

After self-consistency, many methods tried to make agents reason better; a notable one is Reflexion, where the agent reflects through natural-language feedback.

  1. The actor generates a trajectory (held in short-term memory).
  2. An evaluator judges it: correct or incorrect?
  3. Given that feedback, the agent writes a self-reflection: why it thinks the error occurred or why it got this outcome.
  4. The reflection, stored with past experience (long-term memory), changes what the actor does next time.

It works well: self-reflection distils long failed trajectories into relevant experience, rubrics or reward-like signals that serve as self-hints in the future. ReAct + Reflexion clearly beats ReAct alone and reduces hallucination a lot. Try it on a toy version of the household task:

Task: find the pepper shaker in at most 4 moves. The actor's default plan checks cabinets first (where shakers are "more likely"). The evaluator is a fixed check; actor, evaluator and reflection are scripted, not a real LLM.

Turn reflection off and the actor repeats the same failure forever: nothing in the weights changed, only the text in memory.

6 · Q&A ▶ 36:54

Is reflection trained into the weights? No. Reflexion and similar self-reflection techniques involve no fine-tuning or gradient updates; they are implemented with prompts. The paper uses the word "reinforce", but that isn't reinforcement learning, just the self-reflection prompt.

ReAct's hallucination is 0 but its reasoning error is high: how? ▶ 37:40 They are different failures. You can fail without hallucinating: the label may be ambiguous, or you must make sense of the current context. That is not about getting the right tool or information but about interpreting what has happened so far, and errors there count as reasoning errors.

So ReAct is CoT plus acting and observing? ▶ 38:29 CoT is literally one prompt, one pass. ReAct is a multi-step loop, so the model can revise its own errors and pull in new information, a richness CoT lacks; the model decides inside the loop when it's done. (Reasoning modules get a deep dive in two weeks.)

Is reflection a kind of distillation, and does it risk overfitting? ▶ 39:30 "Distil" here isn't classic distillation (training on another model's outputs). It means the model takes a long record of what happened and compresses it into something shorter; "abstract" or "synthesise" would do as well.

Key takeaways

  1. Agent = LLM core + planning/reasoning + memory + tools/actions, acting in an environment. Different papers use different labels for the same loop.
  2. For an agent, reasoning is an internal action that updates its own state; it makes the observation→action jump explainable and generalisable.
  3. CoT can produce convincing wrong traces; ReAct grounds each thought in observations, cutting hallucination (56% → 0% of failures) at the cost of more reasoning and search errors.
  4. Self-consistency samples many CoT paths and takes the most consistent answer.
  5. Reflexion turns failed trajectories into short written lessons stored in memory, with no gradient update; ReAct + Reflexion beats ReAct.
