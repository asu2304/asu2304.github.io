Why the Perceptron Learning Algorithm Converges

In L10 we worried that the corrections might undo each other forever. They can't, if the data are linearly separable. Let $w^*$ be a unit-length separating vector and track the cosine of the angle between $w^*$ and the current $w$. After $k$ updates the numerator of that cosine has grown by at least $k\delta$, while the squared denominator has grown by at most $k$. So the cosine grows like $\sqrt{k}$. A cosine can never go above 1, so $k$ must be finite.

1 · The definition and the theorem

Definition. Two sets $P$ and $N$ of points in $n$-dimensional space are absolutely linearly separable if there exist $n+1$ real numbers $w_0,w_1,\dots,w_n$ such that

$$\textstyle\sum_{i=1}^n w_ix_i\ \ge\ w_0\ \text{ for every } x\in P,\qquad \sum_{i=1}^n w_ix_i\ <\ w_0\ \text{ for every } x\in N .$$

These numbers are exactly the weights we want to find. (Here $w_0$ plays the role of the threshold, as in L8 before we folded it into the sum.)

Theorem. If the sets $P$ and $N$ are finite and linearly separable, the perceptron learning algorithm updates the weight vector only a finite number of times. In other words, if the vectors in $P$ and $N$ are tested cyclically one after the other, a weight vector $w_t$ that separates $P$ from $N$ is found after a finite number of steps $t$.

So the loop while not converged from L10 is not an infinite loop, provided the data are finite and separable.

2 · Setting up: one set, unit vectors, and $w^*$

Three changes of notation make the proof short. None of them changes the problem.

  1. Flip the negatives. If $x\in N$ we want $w^\top x<0$, which is the same as $w^\top(-x)>0$. So $-x$ behaves like a positive point. Let $N^-$ be the set of negations of all points in $N$, and $P'=P\cup N^-$. Now there is only one condition: $w^\top p\ge0$ for every $p\in P'$.
  2. One update rule. The algorithm becomes: pick a random $p\in P'$; if $w^\top p<0$, set $w\leftarrow w+p$. The second if (subtract a negative point) has disappeared, because subtracting $x$ is adding $-x$.
  3. Normalise the inputs. Replace every $p$ by $p/\lVert p\rVert$. Since $\lVert p\rVert>0$, the sign of $w^\top p$ is unchanged, so the same $w$ works. Now $\lVert p\rVert=1$ for every point.
  4. Name the answer. The data are separable, so some separating vector exists. Call its normalised version $w^*$, so $\lVert w^*\rVert=1$. We don't know $w^*$, but we may use the fact that it exists.

3 · The quantity to watch: the angle to $w^*$

Suppose at time step $t$ we inspect the point $p_i$ and find the condition violated, $w_t^\top p_i\le0$. We correct: $w_{t+1}=w_t+p_i$. Let $\beta$ be the angle between $w^*$ and $w_{t+1}$:

$$\cos\beta=\frac{w^*\cdot w_{t+1}}{\lVert w_{t+1}\rVert}.$$

There is no $\lVert w^*\rVert$ in the denominator because $w^*$ is a unit vector. The idea is to bound the numerator from below and the denominator from above.

One more definition. Take the dot product of $w^*$ with every point $p_1,\dots,p_m$ of $P'$. Each is a real number; let $\delta$ be the smallest:

$$\delta=\min_{j}\ w^*\cdot p_j,\qquad\text{so}\qquad w^*\cdot p_j\ \ge\ \delta\ \text{ for every } j .$$

4 · The numerator grows at least linearly

  1. Substitute the update: $$w^*\cdot w_{t+1}=w^*\cdot(w_t+p_i)=w^*\cdot w_t+w^*\cdot p_i .$$
  2. Whichever point $p_i$ was picked, $w^*\cdot p_i\ge\delta$. So $w^*\cdot w_{t+1}\ge w^*\cdot w_t+\delta$.
  3. $w_t$ itself came from an earlier correction, $w_t=w_{t-1}+p_j$. Expanding again: $w^*\cdot w_{t+1}\ge w^*\cdot w_{t-1}+2\delta$.
  4. Keep going back to $w_0$. Each correction contributes one $\delta$: $$w^*\cdot w_{t+1}\ \ge\ w^*\cdot w_0+k\delta .$$

Here $w_0$ is the initial weight vector (the random start), not the bias from section 1; the lecture uses the same symbol for both.

Why $k$ and not $t$? We don't correct at every time step: if the picked point already satisfies the condition, $w$ is unchanged and no $\delta$ appears. So $k$, the number of corrections, satisfies $k\le t$.

5 · The denominator grows at most like $\sqrt{k}$

  1. Work with the square: $$\begin{aligned}\lVert w_{t+1}\rVert^2&=(w_t+p_i)\cdot(w_t+p_i)\\&=\lVert w_t\rVert^2+2\,w_t\cdot p_i+\lVert p_i\rVert^2 .\end{aligned}$$
  2. We only corrected because $w_t\cdot p_i\le0$, so the middle term is $\le0$. Dropping it can only make the sum bigger: $$\lVert w_{t+1}\rVert^2\le\lVert w_t\rVert^2+\lVert p_i\rVert^2 .$$
  3. The inputs are normalised, so $\lVert p_i\rVert^2=1$: $\lVert w_{t+1}\rVert^2\le\lVert w_t\rVert^2+1$.
  4. By the same induction, each correction adds at most 1: $$\lVert w_{t+1}\rVert^2\ \le\ \lVert w_0\rVert^2+k .$$

6 · Putting them together

The numerator is at least something and the denominator is at most something, so the fraction is at least their ratio:

$$\cos\beta\ \ge\ \frac{w^*\cdot w_0+k\delta}{\sqrt{\lVert w_0\rVert^2+k}}$$ For large $k$ this lower bound grows roughly like $\delta\sqrt{k}$.

If the algorithm never converged, $k$ would grow without limit, and so would this lower bound on $\cos\beta$. But $\cos\beta\le1$. So $k$ cannot go to infinity: there is a maximum number of corrections, and after them every point satisfies the condition. That proves the theorem.

The intuition in L10 left a worry: fix one point, then another, and why aren't these updates counterproductive? The proof answers it. Individual updates may well undo each other's effect on particular points, but every update turns $w$ measurably closer to the fixed direction $w^*$, and that can only happen finitely often.

Going beyond the video: how many updates, at most? Take $w_0=0$ for simplicity. Then the bound reads $\cos\beta\ge\delta\sqrt{k}$, and $\cos\beta\le1$ gives $$k\ \le\ \frac{1}{\delta^2}.$$ $\delta$ is the smallest cosine between $w^*$ and any (normalised) data point: how comfortably the data are separated. A thin gap means a small $\delta$ and possibly many updates. This also shows why the definition needs the strict "$<$": it makes $\delta>0$, without which the bound says nothing. My ML notes prove the same result in the form "at most $R^2/\gamma^2$ mistakes" (L54), which is this bound without normalising the inputs.

Do we always need to hand-code the threshold?No. We learn all the parameters: the threshold $w_0$ and also $w_1,\dots,w_n$.

Key takeaways

  1. Theorem: for finite, linearly separable $P$ and $N$, the perceptron learning algorithm makes only finitely many updates.
  2. Flip the negatives ($P'=P\cup N^-$) and normalise the inputs: one condition, $w^\top p\ge0$, and one update, $w\leftarrow w+p$.
  3. With $\delta=\min_j w^*\cdot p_j$: the numerator $w^*\cdot w$ grows by at least $\delta$ per correction; $\lVert w\rVert^2$ grows by at most 1.
  4. Hence $\cos\beta$ is at least $(w^*\cdot w_0+k\delta)/\sqrt{\lVert w_0\rVert^2+k}$, which grows like $\sqrt{k}$; since $\cos\beta\le1$, $k$ is bounded.
  5. The guarantee is only for separable data; non-separable functions need something more than one perceptron.
