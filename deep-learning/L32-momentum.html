Momentum-Based Gradient Descent

Gradient descent crawls across gentle slopes because it only listens to the current, tiny gradient. Momentum keeps a running history $u_t$ of all past gradients, exponentially weighted, and moves by that instead. If you keep being pushed the same way, the steps grow. The price: it builds up so much speed that it overshoots the minimum and makes U-turns. It still gets there much sooner.

1 · The problem: gentle slopes take forever

From L30 and L31: gradient descent takes a long time to cross regions with a gentle slope (on a contour map, successive rings far apart). There the gradients are small, so the updates $\eta\,\nabla w_t$ are small, and it takes a huge number of tiny steps to get off the flat surface.

2 · The intuition: ask for directions

You stand at the Velachery gate of IIT Madras and ask how to get to the Phoenix Market City mall. "Turn right." Being cautious, you take a few small steps that way. After a while you ask someone else: "Go right." Now you're more confident and walk a bit faster. A third person also says "right", and you speed up again. If you are repeatedly told to go in the same direction, you should gain confidence and take bigger steps in that direction.

On a gentle slope each individual gradient is small, but they all point the same way. If we accumulate them, we can move fast and get off the plateau quickly, just as a ball rolling down a slope gains momentum: slow at first on the gentle part, then faster and faster because it is constantly being pushed the same way.

3 · The update rule

$$u_t=\beta\,u_{t-1}+\nabla w_t,\qquad w_{t+1}=w_t-\eta\,u_t$$

with $u_{-1}=0$ and $0\le\beta<1$. The same two lines are applied to $b$. Here $\nabla w_t$ is the partial derivative of the loss with respect to $w$, evaluated at $w=w_t,\ b=b_t$.

$u_t$ is the history vector. Plain gradient descent, $w_{t+1}=w_t-\eta\,\nabla w_t$, only follows the current instruction; momentum also respects the fact that you've been told to go this way many times. Unroll the recursion to see what $u_t$ contains:

  1. $u_0=\beta\,u_{-1}+\nabla w_0=\nabla w_0$ (there is no history yet).
  2. $u_1=\beta\,u_0+\nabla w_1=\beta\,\nabla w_0+\nabla w_1$.
  3. $u_2=\beta\,u_1+\nabla w_2=\beta^2\,\nabla w_0+\beta\,\nabla w_1+\nabla w_2$.
  4. In general $\displaystyle u_t=\sum_{\tau=0}^{t}\beta^{\,t-\tau}\,\nabla w_\tau$.

So $u_t$ is an exponentially weighted sum of the current and all past gradients. With the typical $\beta=0.9$, the current gradient gets weight 1, the previous one 0.9, the one before $0.9^2=0.81$, and so on: old gradients count for less and less, but everything is accumulated. Because $u_t$ contains the current gradient plus the history, on a flat surface where all the gradients agree it is larger than the current gradient alone, so the steps are larger.

Going beyond the video: how much faster? If the gradient stays at a constant $g$ (a uniform gentle slope), $u_t=g\,(1+\beta+\dots+\beta^t)\to g/(1-\beta)$. With $\beta=0.9$ the steps become up to 10× those of gradient descent; with $\beta=0.99$, 100×. The "current step" readout above shows this sum approaching its limit.

4 · The code

The lecture's code is the gradient descent code with two extra lines. For convenience it initialises $w=b=-2$, keeps $\eta=1$, sets $\beta=0.9$, and starts the histories at zero:

w, b, η, β = −2, −2, 1.0, 0.9 v_w, v_b = 0, 0 # u_{−1} = 0 for epoch in 1 … max_epochs: dw, db = 0, 0 for (x, y) in data: # true gradient: sum over all points dw += grad_w(w, b, x, y); db += grad_b(w, b, x, y) v_w = β·v_w + dw; v_b = β·v_b + db # accumulate history w = w − η·v_w; b = b − η·v_b # move by the history

Two things happen, and the lecture points out both:

  • It is fast. Even in the gentle regions momentum takes large steps, because the history carries it along. In the lecture's animation (25 iterations per second), after 50 iterations momentum is already at a very low loss while gradient descent is still at a high loss. Check the readouts at $t=50$.
  • It overshoots. It rushes down into the valley, shoots past the minimum and up the other side, makes a U-turn, comes back, overshoots again, and so on. It oscillates in and out of the minimum valley before settling.

Set $\beta=0$ and the two paths coincide: momentum with no history is gradient descent. Push $\beta$ towards 0.99 and the U-turns get longer.

6 · Is moving fast always good?

Back to the mall. After many people have said "go right", you're on a scooter going fast. You zoom past the mall, take a U-turn, people now say "go left", you speed up again, overshoot again, U-turn again… The U-turns on the contour map are exactly this. The lecture shows the same thing on a second input where flat regions surround a narrow, steep valley: like a ball released on the rim, momentum rolls down, up the far side, back again, many times.

Verdict. Momentum-based gradient descent oscillates in and out of the minimum valley as the momentum carries it out, and it takes several U-turns before converging. Despite these U-turns it still converges faster than vanilla gradient descent, just as the person on the scooter still reaches the mall before the person walking. The next question: can we keep the speed but reduce the oscillations? That is Nesterov accelerated gradient descent.

Key takeaways

  1. Gradient descent is slow on gentle slopes because each update $\eta\,\nabla w_t$ is tiny.
  2. Momentum: $u_t=\beta u_{t-1}+\nabla w_t$, $w_{t+1}=w_t-\eta u_t$, with $u_{-1}=0$ and typically $\beta=0.9$.
  3. Unrolled, $u_t=\sum_{\tau=0}^{t}\beta^{t-\tau}\nabla w_\tau$: an exponentially weighted sum of the current and all past gradients.
  4. Consistent gradients add up, so momentum escapes plateaus quickly; $\beta=0$ recovers plain gradient descent.
  5. The built-up speed makes it overshoot and U-turn around the minimum, yet it still converges faster than gradient descent.
