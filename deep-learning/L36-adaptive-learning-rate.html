Why We Want Adaptive Learning Rates

The gradient is what it is: large on steep slopes, small on gentle ones. What we can change is the multiplier, the learning rate. Sparse features give a second, sharper reason to do so. The gradient of a weight is a sum over training points of terms multiplied by that weight's input, so a feature that is almost always 0 gets a tiny gradient and its weight barely learns, even when the feature is important. We want a learning rate per parameter that adapts to this automatically.

1 · Where we are

So far: momentum to move faster, NAG to correct momentum's overshooting, stochastic and mini-batch versions, and learning-rate schedules. Along the way a wish kept coming up: on steep regions we want a small learning rate, on gentle regions a large one. The rate should look at the history and the current position and speed up or slow down accordingly.

We can't change the gradients: in a steep region they are large, in a gentle region small. But the multiplying factor, the learning rate, can be changed, and that scales the updates up or down.

2 · A neuron with several inputs

A new piece of notation. Instead of one input, the neuron now has four inputs $x^1,x^2,x^3,x^4$ (plus a bias, ignored for the moment), with weights $w^1,\dots,w^4$, and $f(\mathbf{x})=\sigma(\mathbf{w}^\top\mathbf{x})$. Subscripts still index training points ($\mathbf{x}_1,\dots,\mathbf{x}_m$); superscripts index the features within one point. So movie 1 is $\mathbf{x}_1=(x_1^1,x_1^2,x_1^3,x_1^4)$.

For a single training point $(\mathbf{x},y)$ with squared-error loss, the derivative is the same as for the one-input neuron, except the final factor is the input that this weight multiplies:

$$\frac{\partial\mathscr{L}}{\partial w^1}=\underbrace{(f(\mathbf{x})-y)\,f(\mathbf{x})\,(1-f(\mathbf{x}))}_{\text{same for every weight}}\;x^1,\qquad \frac{\partial\mathscr{L}}{\partial w^2}=(f(\mathbf{x})-y)\,f(\mathbf{x})\,(1-f(\mathbf{x}))\;x^2 .$$

That last factor appears because, when the chain rule reaches $\mathbf{w}^\top\mathbf{x}=w^1x^1+w^2x^2+\dots$, the derivative with respect to $w^2$ kills every term except $w^2x^2$ and leaves $x^2$. Over $m$ training points we just sum:

$$\nabla w^2=\sum_{i=1}^{m}\big(f(\mathbf{x}_i)-y_i\big)\,f(\mathbf{x}_i)\,\big(1-f(\mathbf{x}_i)\big)\;x_i^2$$

3 · Sparse features get tiny gradients

A feature is sparse if it is 0 for most training points. Example: data on the last 1000 Bollywood movies with the feature "is the actor Aamir Khan?". He acts in very few films, so the feature is 1 for maybe four or five movies and 0 for all the others. Real-world data are full of such features.

  1. In the sum for $\nabla w^2$, every term is multiplied by $x_i^2$. If 990 of 1000 values are 0, then 990 of the terms vanish.
  2. So the total derivative for a weight attached to a sparse feature is small.
  3. The update $w_{\text{new}}=w_{\text{old}}-\eta\,\nabla w$ is therefore small too: that weight barely moves.

Why not just let it be? Because sparse features can be important. Christopher Nolan directs a film every few years, so "is the director Nolan?" is a sparse feature. But his films are generally good, so when the feature is present it strongly decides the outcome. $w$ decides how much the feature contributes to $\mathbf{w}^\top\mathbf{x}$; if its weight starts small and, over 1000 steps, gets only a few tiny updates, the model never uses that information.

The wish. Since we know the derivatives of sparse features will be small, give those parameters a larger learning rate; there is no need to be conservative with updates that are rare anyway. Dense features can keep a smaller rate. So: a different learning rate for each parameter, depending on how frequent its feature is.

Test the claim. 200 training points; features $x^1,x^3,x^4$ are dense (uniform in $[-1,1]$), $x^2$ is a 0/1 feature that is on in only a few points but has the largest true weight. Plain gradient descent, all weights starting at 0, one shared $\eta$:

With x² on in 5% of points, the dense weights settle in about 100 iterations while $w^2$ is still far from its true value hundreds of iterations later, and the model's predictions on exactly those "Nolan movies" stay poor. Raise the frequency to 50% and $w^2$ learns as fast as the rest. Then go back to a sparse setting and turn up the multiplier on $w^2$'s learning rate alone: the lag disappears. That is the wish, done by hand.

4 · What we need

Hand-tuning won't scale: there can be millions of features, and we cannot write if-else rules ("if this feature is sparse, raise its rate"). We need update equations that, without heuristics, automatically give a high learning rate to parameters of sparse features and a lower one to dense ones, and more generally adapt to the slope. Turning this intuition into an update rule is the job of the next lecture, AdaGrad.

Going beyond the video: a hint of the answer. A parameter's own gradient history already "knows" whether its feature is sparse: its past gradients are mostly zero. AdaGrad divides each parameter's step by the square root of the sum of its past squared gradients, so rarely-updated parameters get relatively large steps. That is the per-parameter multiplier in the demo, computed automatically.

Key takeaways

  1. Gradients are fixed by the surface; the learning rate is the knob we can adapt.
  2. We want small rates on steep regions and large rates on gentle ones.
  3. With several inputs, $\nabla w^j=\sum_i(f(\mathbf{x}_i)-y_i)f(\mathbf{x}_i)(1-f(\mathbf{x}_i))\,x_i^j$: each term is multiplied by that weight's own input.
  4. For a sparse feature most terms are zero, so its weight gets small gradients and small updates, even if the feature is important (the Nolan example).
  5. Goal: a separate, automatically adapted learning rate per parameter, large for sparse features. That leads to AdaGrad.
