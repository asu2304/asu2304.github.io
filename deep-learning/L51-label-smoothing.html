Injecting Noise at the Outputs: Label Smoothing

The previous lecture corrupted the inputs; this one corrupts the targets. Instead of a one-hot label that puts all the probability on the correct class, take a small mass $\varepsilon$ away from it and spread it over the other classes. The cross-entropy loss then becomes $(1-\varepsilon)$ times the original loss plus $\varepsilon$ times an extra term, which acts as a regulariser.

1 · Hard targets invite overfitting

Take digit classification with 10 classes, $0,\dots,9$, and an image of a 2. The true distribution $p$ is one-hot: all the probability mass on class 2, zero everywhere else. We train the predicted distribution $q=\hat f(x)$ to match it by minimising the cross-entropy

$$\mathcal L(\theta)=-\sum_{i=0}^{9}p_i\log q_i=-\log q_2 ,$$

where only the term with $p_i=1$ survives. With a lot of parameters this error can be driven to zero, and that is overfitting: the network learns to map each training input exactly to its output. Besides, the labels themselves might be noisy, so trusting them completely is not wise either.

2 · Soft targets

So don't trust the hard targets fully. Take a small probability mass $\varepsilon$ away from the correct label and distribute it over the other labels:

hard target$1$$0$
soft target$1-\varepsilon$$\varepsilon/9$

The output has been corrupted, but only a little: $\varepsilon$ is small, so most of the mass is still on the correct label. What changes is the loss. Earlier only one term of $-\sum_ip_i\log q_i$ survived; now every term has a non-zero weight.

3 · The new loss is "loss + regulariser"

  1. Plug the soft targets into cross-entropy: $$\tilde{\mathcal L}(\theta)=-(1-\varepsilon)\log q_2\;-\;\sum_{j\ne2}\frac{\varepsilon}{9}\log q_j .$$
  2. The first term is the old loss $\mathcal L(\theta)=-\log q_2$, now weighted by $1-\varepsilon$.
  3. Call what is left $\varepsilon\,\Omega(\theta)$, with $\Omega(\theta)=-\tfrac19\sum_{j\ne2}\log q_j$: $$\tilde{\mathcal L}(\theta)=(1-\varepsilon)\,\mathcal L(\theta)+\varepsilon\,\Omega(\theta).$$
The same shape as every regulariser so far, $\mathcal L(\theta)+\Omega(\theta)$: we no longer minimise the true loss, but a slightly corrupted version of it. $\Omega$ grows when any wrong class gets a probability close to 0, so it pushes back against an infinitely confident prediction.

In the video the per-class weight on the wrong labels is said quickly as "$\varepsilon$ times $\log$ …"; I've written $\varepsilon/9$ so that the soft target still sums to 1, which is what "take a small mass away and distribute it" means. The decomposition is the same either way.

4 · See the regulariser at work

Let the network's output be a softmax in which the correct class has logit $z$ and the other nine have logit 0, so $q_2=e^z/(e^z+9)$. Move $z$ and watch the two losses. With the hard target the loss keeps falling as $z\to\infty$: the network is rewarded for ever-larger weights and ever more confidence. With soft targets the loss has a finite minimum, exactly where $q$ equals the soft target.

Going beyond the video. The name "label smoothing" comes from Szegedy et al. (2016, Inception-v3), who mix the one-hot label with a uniform distribution over all $K$ classes: the correct class gets $1-\varepsilon+\varepsilon/K$ and every other class $\varepsilon/K$. It is the same idea with slightly different bookkeeping. In the demo's setting the soft-loss minimum sits at $z^\star=\log\frac{9(1-\varepsilon)}{\varepsilon}$, so for $\varepsilon=0.1$ the network has no incentive to push the logit gap beyond about 4.4.

Key takeaways

  1. One-hot targets plus cross-entropy reward ever more confident outputs, and a large network can drive this loss to zero: overfitting.
  2. Label smoothing: give the correct class $1-\varepsilon$ and spread $\varepsilon$ over the other classes (soft targets instead of hard ones).
  3. The loss becomes $(1-\varepsilon)\mathcal L(\theta)+\varepsilon\,\Omega(\theta)$: the original loss plus a regulariser.
  4. With soft targets the optimum is a finite, slightly unconfident prediction, so there is no pull towards infinite logits.
