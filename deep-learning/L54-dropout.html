Dropout

Ensembles help, but training and running $k$ large networks is prohibitively expensive. Dropout gets the averaging effect almost for free: for every mini-batch, randomly drop neurons to get a "thinned" network, train that one, and let all $2^n$ possible thinned networks share the same weights. At test time, run the single full network with each neuron's output scaled by its retention probability $p$.

1 · Why ensembles are hard for deep networks

The last lecture (L53) showed that averaging several models helps. For deep networks there are two ways to build the ensemble, and both are expensive:

  • Option 1: train several networks with different architectures.
  • Option 2: train the same architecture on different subsets of the training data (bagging).

Either way the cost hits twice. Training one deep network is already expensive, and now we need $k$ of them. And at test time, where we want answers fast, every test input must go through all $k$ networks before their outputs are combined. Dropout addresses both problems: it effectively trains many networks without paying for $k$ trainings, and at inference it uses one network plus a simple trick to get the averaging effect.

2 · The idea: drop units, get a thinned network

Start from the original network and drop some neurons at random. What remains is a network with a different architecture, just as in option 1. This is temporary: the drop applies to the current training instance (or mini-batch), and the next one gets a different drop.

  • Each node is retained with a fixed probability $p$, e.g. kept with 80% chance and dropped with 20%, decided afresh for every mini-batch.
  • With $n$ droppable nodes, each is either kept (1) or dropped (0), so a 0/1 vector of length $n$ picks out one thinned network. There are $2^n$ such vectors, so $2^n$ possible networks.

If training $k$ networks was too expensive, how can we possibly train $2^n$? Two tricks.

trickwhat it means
1. Share the weightsAll $2^n$ networks use the same weight matrices. A weight is present in only some of the networks (half of them, if $p=\tfrac12$), but wherever it appears it is the same copy.
2. Sample a network per stepWe never build the $2^n$ networks up front. For each training instance / mini-batch, sample one thinned network by dropping nodes at random, and train that.

3 · Training, step by step

  1. Initialise all the weights of the one base network. With $n$ inputs, two hidden layers of $n$ nodes and one output (ignoring biases), that is $n^2+n^2+n=2n^2+n$ weights.
  2. First mini-batch: drop some nodes to get a thinned network. Do forward propagation through it to get the loss, then back-propagate.
  3. Update only the weights that took part. A weight attached to a dropped node did not participate in the forward pass, so it gets no gradient and is not updated. It works both ways: only the active weights are used forward and updated backward.
  4. Second mini-batch: sample a new thinned network (a different random drop). Again update only the participating weights.
  5. Shared weights carry over. A weight $w$ active in both networks was updated at step 1 to $w_1$; at step 2 it starts from $w_1$, not $w_0$. Weights active in both batches got two updates, those active in only one got one.

So although it looks like a different network every step, it is one network from which different nodes are temporarily removed.

With $n$ large, $2^n$ is astronomically large: most thinned networks are sampled once or never. That's fine, because of weight sharing. Every weight is trained whenever some sampled network contains it. If each node is kept with probability 0.8, a weight between two droppable nodes is present when both are kept: $0.8\times0.8=0.64$. Over 1,000 steps it gets about 640 updates.

4 · Test time: scale by $p$

At test time we can't sample $2^n$ networks, pass the input through all of them and combine. Instead, a neat trick: each node was present only a fraction $p$ of the time during training, say 80%. It "took part in only 80% of the discussions", so trust its output only that much: multiply every node's output by $p$ before it goes to the next layer.

Test time: one pass through the full network, with the output of every (droppable) neuron scaled by its retention probability $p$. This stands in for averaging the outputs of all the thinned networks.

How good a stand-in is it? Below, a fixed random network (1 input, two hidden layers of 16, 1 output) is turned into an ensemble by sampling 300 thinned networks and averaging their outputs. Compare that average with the single weight-scaled network.

Going beyond the video. When everything between the dropped units and the output is linear, scaling by $p$ gives exactly the ensemble average (the expectation of a product of independent masks is a product of $p$'s); with non-linearities it is an approximation, usually a good one, as the demo shows. Frameworks today use inverted dropout: divide the kept activations by $p$ during training and do nothing at test time. It is the same model, with the scaling moved to training. Note also that frameworks specify the drop rate $1-p$, e.g. Dropout(0.2) for $p=0.8$.

5 · How it is implemented: a masking noise

You don't visit every node and flip a coin one by one. For a layer of $n$ nodes, draw a random 0/1 vector $m$ of length $n$, with about 80% ones and 20% zeros, and multiply the layer's output element-wise by it. A masked node outputs 0, which is the same as not taking part in the computation at all. So dropout applies a masking noise to the hidden units, the hidden-layer cousin of the input noise of L50.

6 · Why it regularises: no co-adaptation

With all nodes always present, neurons can co-adapt. Say the task is to tell whether an image contains a face. One neuron learns to detect noses, another eyes, and a lazy one does little, because the others do the work. Or neurons divide the job: "you fire for noses, I fire only for clearly visible eyes". (Neurons don't literally talk, but this kind of reliance does arise.)

Now drop nodes at random. An image with a nose comes in and the nose detector has been dropped: no one in the layer detects noses. The others can no longer rely on it, since it is unreliable, sometimes there and sometimes not. So either several nodes learn to detect noses, or other nodes learn to detect the face without the nose, from the eyes or even the eyebrows, which the network may never have used before. Each node has to act more independently and take more responsibility, and the network becomes more robust.

Key takeaways

  1. Ensembles of deep networks are expensive at training time ($k$ networks) and at test time ($k$ forward passes); dropout avoids both.
  2. Each mini-batch, every node is kept with probability $p$; the result is one of $2^n$ thinned networks, and only its weights are used and updated.
  3. All thinned networks share one set of weights, so every weight keeps being trained (about $p^2$ of the steps for a weight between two droppable nodes) even though most networks are never sampled.
  4. At test time use the full network and scale each neuron's output by $p$, approximating the average over all thinned networks.
  5. Implemented as a random 0/1 mask on each layer's output; it prevents co-adaptation and forces redundant, robust features.
