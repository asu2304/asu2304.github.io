LightGBM: Histograms, Leaf-wise Growth, GOSS and EFB

XGBoost (D3) tells us what to optimise: every tree is chosen by the gain formula built from per-point gradients $g_i$ and Hessians $h_i$. LightGBM keeps exactly that objective and attacks cost. Finding a split means scanning every data point for every feature, so LightGBM makes each scan cheaper (histograms), spends its leaf budget where the loss falls fastest (leaf-wise growth), uses fewer data points (GOSS) and fewer features (EFB).

Not part of the DA5400 lectures. Main source: G. Ke et al., LightGBM: A Highly Efficient Gradient Boosting Decision Tree, NeurIPS 2017; parameter names from the LightGBM documentation. Previous: D3 · Next: D5.

1 · Where the time goes

Recall the round of gradient boosting from D1–D3. At round $m$ we have $F_{m-1}$, compute for every training point

$$g_i=\frac{\partial \ell(y_i,F)}{\partial F}\Big|_{F_{m-1}(x_i)},\qquad h_i=\frac{\partial^2 \ell(y_i,F)}{\partial F^2}\Big|_{F_{m-1}(x_i)},$$

grow a tree $f_m$ greedily, and update $F_m=F_{m-1}+\eta f_m$. Growing the tree is the L44 recipe ("find the best question, split, repeat on each side") with information gain replaced by D3's score. For a leaf $I$ split into $I_L$ and $I_R$, with $G=\sum_{i\in I}g_i$ and $H=\sum_{i\in I}h_i$:

$$\text{Gain}=\frac12\left[\frac{G_L^2}{H_L+\lambda}+\frac{G_R^2}{H_R+\lambda}-\frac{(G_L+G_R)^2}{H_L+H_R+\lambda}\right]-\gamma ,\qquad w^\star=-\frac{G}{H+\lambda}.$$

To score every threshold of one feature, sort the points in the leaf by that feature and sweep left to right, keeping running sums $G_L,H_L$ (then $G_R=G-G_L$, $H_R=H-H_L$). One sweep touches every point, so finding one split costs

$$O(\#\text{data in the leaf}\times\#\text{features}),$$

and across a whole tree level that's $O(n\,d)$. With millions of rows and thousands of features, that sweep is nearly all of the training time. LightGBM cuts each factor:

2 · Histogram-based split finding

  1. Bin once, before training. Each feature's values are mapped to at most max_bin integer bins (LightGBM's default is 255), with bin edges chosen from the data's distribution so busy regions get more bins. The data set is stored as small bin indices from then on.
  2. Build a histogram per leaf. For each feature, one pass over the leaf's points accumulates, per bin $b$, $\;G_b=\sum_{i\in\text{bin }b}g_i\;$ and $\;H_b=\sum_{i\in\text{bin }b}h_i$ (plus a count).
  3. Scan bins, not points. The candidate thresholds are the bin boundaries. Prefix sums $G_L(k)=\sum_{b\le k}G_b$, $H_L(k)=\sum_{b\le k}H_b$ go straight into the gain formula. That scan costs $O(\#\text{bins})$, independent of $n$.
  4. Histogram subtraction. After splitting a parent into two children, build the histogram of the smaller child only; the other is $\text{hist}(\text{parent})-\text{hist}(\text{smaller child})$, a subtraction over bins.

Building a histogram still touches every point once, but it needs no sorting and is a cheap, cache-friendly addition, and the subtraction trick roughly halves even that. The price is that thresholds can only fall on bin boundaries. The demo shows how little that usually costs: with a few dozen bins, the best binned split captures almost all of the exact best gain.

Going beyond. D3's approximate algorithm also restricts thresholds to candidate split points, from a weighted quantile sketch (weights $h_i$). The difference is mainly in engineering: LightGBM bins once globally and reuses the integer bins everywhere. XGBoost later added a histogram method of its own, so "histograms" is no longer what separates the two libraries.

3 · Leaf-wise vs level-wise growth

L44 grew a tree by splitting every node until a depth limit, then cross-validated the depth. That's level-wise (depth-wise) growth: all leaves at depth $k$ are split before any at depth $k+1$. LightGBM grows leaf-wise (best-first): among all current leaves, split the one whose best split has the largest gain, and stop at num_leaves leaves.

Same number of leaves, usually a lower training loss. Each leaf-wise step takes the largest available loss reduction, so with a budget of $T$ leaves it typically reaches a lower training loss than a level-wise tree with $T$ leaves. But leaf-wise trees can become very deep and lopsided, chasing a few points, which is the overfitting of L66. LightGBM's controls: num_leaves, max_depth, min_data_in_leaf, min_sum_hessian_in_leaf.

4 · GOSS: Gradient-based One-Side Sampling

AdaBoost (L68) had explicit point weights $D_t(i)$: points the ensemble gets wrong carry more weight. In L71 we saw why: the exponential loss's slope grows like $e^{-y_iH(x_i)}$. Gradient boosting has no separate weights, but $|g_i|$ plays the same role. A point with a small gradient is already fitted well and moving $F$ there barely changes the loss; a point with a large $|g_i|$ is a "hard" point. That suggests a smarter subsample than D2's uniform one.

  1. Sort the points by $|g_i|$. Keep the top $a\cdot100\%$ (the large-gradient set $A$), all of them.
  2. From the remaining $(1-a)\,n$ points, sample $b\cdot100\%$ of $n$ uniformly at random (the set $B$). Drop the rest for this tree.
  3. Multiply $g_i$ and $h_i$ of the points in $B$ by $\dfrac{1-a}{b}$, since each sampled point stands in for $\frac{1-a}{b}$ small-gradient points.
  4. Grow the tree on $A\cup B$ with these weighted statistics, using the usual gain formula.

The factor makes the sums unbiased: for any leaf, $\mathbb E[G]$ over the random draw of $B$ equals the full-data $G$ (and likewise $H$). The gain is a ratio of squared sums, so its estimate is only approximately unbiased; the paper bounds the error and shows it shrinks as $n$ grows. Because the points that dominate the gain (large $|g_i|$) are never dropped, GOSS estimates the gain with much less variance than a uniform sample of the same size.

Why $\frac{1-a}{b}$, going beyond. The small-gradient set has $(1-a)n$ points and we draw $bn$ of them uniformly, so each one is included with probability $\frac{bn}{(1-a)n}=\frac{b}{1-a}$. For any leaf, $\mathbb E\big[\sum_{i\in B\cap\text{leaf}}\tfrac{1-a}{b}g_i\big]=\sum_{i\in\text{rest}\cap\text{leaf}}g_i$: the standard inverse-probability (Horvitz–Thompson) weight. GOSS pays off mainly when $n$ is large; on small data sets, plain row subsampling (D2) is the simpler and safer choice (a rule of thumb, not a result from the paper).

5 · EFB: Exclusive Feature Bundling

Real high-dimensional data is usually sparse: one-hot encodings, bag-of-words (the spam features of L46–L48), indicator columns. Many features are mutually exclusive: they are rarely non-zero in the same row. Exclusive features can share one column without losing information.

  1. Which features to bundle is a graph-colouring problem: features are vertices, and an edge's weight counts the rows where both are non-zero (conflicts). Optimal bundling is NP-hard, so LightGBM goes greedy: order features (for example by degree), and put each one into the first bundle whose total conflicts stay below a tolerance $K$, else open a new bundle.
  2. How to merge: give each feature in a bundle its own range of bins by adding an offset. If feature A has bins $[0,10)$ and B has $[0,20)$, store B's bins as $[10,30)$. The bundle's histogram then contains each original feature's histogram side by side, so splits on A or B can still be found.

Histogram building now costs $O(n\times\#\text{bundles})$ instead of $O(n\times\#\text{features})$. A small $K$ trades a little accuracy (conflicting rows lose information) for fewer bundles.

6 · Categorical features, briefly

LightGBM can also split a categorical feature directly instead of one-hot encoding it (for features declared categorical). For a leaf, it sorts the categories by their accumulated statistic $\sum g/\sum h$, in effect the leaf value each category would want on its own, and then scans that ordering like a numeric feature, splitting the categories into a left group and a right group. Settings such as max_cat_to_onehot and cat_smooth control and regularise this. High-cardinality categoricals can still overfit this way, which is the problem CatBoost attacks head-on in D5.

Key takeaways

  1. LightGBM optimises the same second-order objective as XGBoost (D3); its contributions are about cost.
  2. Histograms: bin features once, accumulate $G_b,H_b$ per bin, scan $\le$ max_bin boundaries; build the smaller child's histogram and get the sibling by subtraction.
  3. Leaf-wise growth splits the highest-gain leaf next: lower training loss for the same number of leaves, but deep, lopsided trees, so cap it with num_leaves, max_depth and min_data_in_leaf.
  4. GOSS keeps all large-$|g_i|$ points (the "hard" points, like AdaBoost's heavy weights) and samples the rest with weight $\frac{1-a}{b}$: an approximately unbiased gain with lower variance than uniform sampling.
  5. EFB merges mutually exclusive sparse features into bundles using bin offsets, cutting the number of histograms to build.
