CatBoost: Categorical Features without Target Leakage

Real tabular data is full of categorical features: city, product id, user id. The most effective encoding replaces each category by the average label seen with it, but done naively that leaks each row's own label into its features, so the model looks brilliant on training data and fails on new data. CatBoost's answer is one idea used twice: only let a row see the labels of rows that come "before" it in a random order. Applied to the encoding that gives ordered target statistics; applied to the boosting residuals, ordered boosting. It also grows oblivious trees: one question per level.

Not part of the DA5400 lectures. Main source: L. Prokhorenkova et al., CatBoost: unbiased boosting with categorical features, NeurIPS 2018 (arXiv:1706.09516); documentation catboost.ai/docs. Previous: D4 · Next: L72 (back to the course).

1 · The categorical-feature problem

A tree (L43–L44) asks numeric questions like "is $x_f\le t$?". A categorical feature with values {Chennai, Delhi, Mumbai, …} has no order, so it has to be encoded first.

2 · Target statistics, and why the obvious one leaks

For row $k$ with category $c=x_k$, the greedy TS averages the labels of all training rows in that category:

$$\hat x_k=\frac{\sum_{j}\mathbb 1[x_j=c]\;y_j}{\sum_j\mathbb 1[x_j=c]}.$$

The sum includes $y_k$ itself. So the feature of row $k$ contains part of its own label, which a test row never gets. Its distribution given $y$ is different at training and test time (the paper calls this a target leakage, leading to a prediction shift).

The extreme case (from the paper): a feature that is unique for every row, like a transaction id, with no relation to $y$. Then each category has one row, $\hat x_k=y_k$, and a single split at $0.5$ classifies the training set perfectly. On test data, every id is new, so the feature is useless. The tree learned "the encoding equals the label", which is only true on the training set.

3 · Smoothing with a prior (the Beta-prior trick again)

Rare categories give noisy averages. Add $a$ pseudo-observations whose label is the prior value $p$ (for example, the overall mean of $y$):

$$\hat x_k=\frac{\sum_j\mathbb 1[x_j=c]\,y_j\;+\;a\,p}{\sum_j\mathbb 1[x_j=c]\;+\;a}.$$

This is exactly the posterior mean we met in L21: with a $\text{Beta}(ap,\;a(1-p))$ prior on a category's probability of $y=1$, the posterior mean after $n_c$ observations with $s_c$ ones is $\frac{s_c+ap}{n_c+a}$. Laplace smoothing in L49 is the special case $a=2,\;p=\tfrac12$. A category seen once is pulled towards $p$; a category seen 1,000 times keeps its own average.

But smoothing does not remove the leak. In the unique-id example, $\hat x_k=\frac{y_k+ap}{1+a}$: still two values, still perfectly separable on training data. Two other fixes and their problems:

  • Hold-out TS: compute the statistics on one part of the data, train on the other. No leak, but each part sees only some of the data.
  • Leave-one-out TS: use all rows except $k$. Sounds perfect, but it still leaks. If every row has the same category with $n^+$ positives, then $\hat x_k=\frac{n^+-y_k+ap}{n-1+a}$, which is smaller exactly when $y_k=1$, so the feature separates the labels perfectly (the paper's counter-example).

4 · Ordered target statistics

Borrow the idea of time: online algorithms only ever use the past. Draw a random permutation $\sigma$ of the training rows and let row $k$ use only the rows that come before it:

$$\hat x_k=\frac{\sum_{j:\;\sigma(j)<\sigma(k)}\mathbb 1[x_j=x_k]\,y_j\;+\;a\,p}{\sum_{j:\;\sigma(j)<\sigma(k)}\mathbb 1[x_j=x_k]\;+\;a}.$$
Why it works. $\hat x_k$ never uses $y_k$, so the relation between $\hat x_k$ and $y_k$ at training time is the same as for a test row, whose TS is computed from the training data. Unlike hold-out TS, every row is used both to train and (for later rows) to compute statistics.

The cost: rows early in the permutation have little "history", so their statistics are noisy (the first row of a category gets just the prior $p$). CatBoost uses several random permutations, so that early, noisy rows differ from tree to tree. At test time, TS are computed from all training data.

5 · The same leak inside boosting: ordered boosting

The paper's second observation: gradient boosting itself has the same kind of leak. At round $m$, the gradient $g_i$ of training row $i$ is computed from $F_{m-1}(x_i)$, but $F_{m-1}$ was itself fitted on row $i$. So training residuals are systematically smaller than the residuals a test row would have, which is the training-vs-test gap of L66 creeping into every round. The fitted trees are biased towards the training points (a prediction shift).

Ordered boosting applies the "only the past" rule again. Conceptually, keep supporting models $M_1,\dots,M_n$, where $M_i$ is trained only on the first $i$ rows of the permutation, and compute row $i$'s residual with $M_{i-1}$, a model that has never seen row $i$. Storing $n$ models is too expensive, so CatBoost uses an approximation: supporting predictions only for prefixes whose lengths grow by powers of two, shared tree structures, and the same permutations as the ordered TS. The library exposes the choice as boosting_type ("Ordered" or "Plain"); ordered mode matters most on small data sets, where the shift is largest.

6 · Oblivious (symmetric) trees

CatBoost's default trees are oblivious: every node at the same depth asks the same question. A depth-$D$ oblivious tree is a list of $D$ conditions $(f_1,t_1),\dots,(f_D,t_D)$ and a table of $2^D$ leaf values. A point's leaf is just the binary number formed by its answers:

$$\text{leaf}(x)=\sum_{k=1}^{D}2^{k-1}\,\mathbb 1\big[x_{f_k}>t_k\big],\qquad f(x)=w_{\text{leaf}(x)}.$$
  • Fast prediction: $D$ comparisons and a table lookup, with no branching, which is fast on CPUs.
  • Regularisation: a level's question must help all leaves at once (it's chosen to maximise the summed gain over every current leaf), so the tree can't chase one corner of the data. That is the opposite philosophy to LightGBM's leaf-wise growth (D4).
  • Cost: less flexible per tree, so you may need more or deeper trees.

7 · Feature combinations

A single categorical feature's TS can miss interactions: "city" and "product" may matter mainly together. CatBoost builds combinations of categorical features greedily while growing a tree: when a split uses a categorical feature, combinations of the categorical features already used in the current tree with the remaining ones become candidates, each converted to its own ordered TS. Enumerating all combinations would explode, so this greedy rule keeps it manageable.

Key takeaways

  1. Target statistics encode a categorical feature by the average label of its category; smoothing with $a$ pseudo-observations of value $p$ is the Beta-prior posterior mean (L21) and generalises Laplace smoothing (L49).
  2. Greedy TS uses a row's own label in its feature, so training and test distributions differ (target leakage). Smoothing and leave-one-out don't fix it.
  3. Ordered TS: compute row $k$'s statistic only from rows before it in a random permutation, so its own label is never used.
  4. Ordered boosting applies the same rule to residuals: a row's gradient comes from a model that hasn't seen it.
  5. Oblivious trees use one question per level: $2^D$ leaves indexed by $D$ bits, fast inference and built-in regularisation.
  6. XGBoost, LightGBM and CatBoost share one objective; they differ in how trees are grown, how splits are found, and how categorical features and leakage are handled.
