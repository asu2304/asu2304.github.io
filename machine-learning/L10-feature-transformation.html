Lecture 10 · PCA, issue 2: non-linear relationships

Feature Transformation: Making Non-linear Relationships Linear

PCA finds linear relationships. Points on a circle obey a perfectly exact rule, but it's quadratic, so PCA says both directions matter. Map each point to a higher-dimensional vector of monomials, $\phi(x)$, and the circle's rule becomes a linear equation: the mapped points lie in a linear subspace, which PCA can find. The catch: the number of monomial features explodes like $d^p$.

Source: this lecture on YouTube (≈18 min). Previous: L9 · Next: L11.

1 · Recap: issue 1 is solved

When $d\gg n$, L9 avoided the $O(d^3)$ eigen-solve of the covariance matrix by solving the $n\times n$ problem for $K=X^\top X$ and converting its eigenvectors into those of the covariance matrix. Issue 2 is different: what if the features are related, but not linearly?

2 · Points on a circle: what PCA sees

Take 2-D data lying on a circle centred at $(a,b)$. PCA first centres the data (moving the centre to the origin), then looks for the direction of largest variance. Around a circle, no direction stands out: every direction captures about the same variance. PCA picks some $w_1$ (which one depends on exactly where the points sit), and $w_2\perp w_1$ captures nearly the same amount.

  • $w_1$ explains a little over 50% of the variance, $w_2$ a little under 50%.
  • With the usual rule "keep enough directions for 95% of the variance", PCA says both directions are needed. No compression.

But the points obey an exact relationship. With features $f_1,f_2$:

$$(f_1-a)^2+(f_2-b)^2=r^2\;\Longleftrightarrow\; f_1^2+f_2^2-2af_1-2bf_2+(a^2+b^2-r^2)=0 .$$

It has $f_1^2$ and $f_2^2$ terms, so it's not linear, and PCA can't see it.

3 · Lift the points: the relationship becomes linear

Map each 2-D point to a 6-D vector of monomials:

$$\phi\!\left(\begin{bmatrix}f_1\\f_2\end{bmatrix}\right)=\begin{bmatrix}1\\ f_1^2\\ f_2^2\\ f_1f_2\\ f_1\\ f_2\end{bmatrix}\in\mathbb R^6,\qquad u=\begin{bmatrix}a^2+b^2-r^2\\ 1\\ 1\\ 0\\ -2a\\ -2b\end{bmatrix}\in\mathbb R^6 .$$

The vector $u$ is built from the circle's parameters, not from any data point. Now the dot product $\phi(x)^\top u$ is exactly the left side of the circle equation, so every data point satisfies

$$\phi(x_i)^\top u=0 .$$
After the map, all the data points are orthogonal to one fixed vector $u$: they lie in a linear subspace of $\mathbb R^6$. The non-linearity has been absorbed into $\phi$; in the mapped space, the relationship is linear, and finding linear structure is exactly what PCA does.

Going beyond the video. The right-hand spectrum is my addition: it's PCA in the 5 non-constant coordinates of $\phi$. Because $f_1^2+f_2^2-2af_1-2bf_2$ is constant across the data, one combination of the centred features has zero variance, so one eigenvalue is ≈ 0 and its eigenvector is proportional to $(1,1,0,-2a,-2b)$, the non-constant part of $u$. Add noise and that eigenvalue becomes small rather than zero.

4 · The general recipe

  1. Transform features from a low dimension to a high one: $x\in\mathbb R^d\mapsto\phi(x)\in\mathbb R^D$, with $D\gg d$.
  2. Hope that in $\mathbb R^D$ the mapped data lives in a low-dimensional linear subspace.
  3. Run PCA on the mapped points. Since $D$ may exceed $n$, use L9's trick: work with the $n\times n$ matrix $\phi(X)^\top\phi(X)$ instead of the $D\times D$ covariance. ($\phi(X)$ means $\phi$ applied to each column of $X$.)

5 · The catch: the number of features explodes

Suppose 4 features (say height, weight, age, …) and you want all relationships up to cubic ones, such as height × weight × age. The map needs a constant, every single feature, every product of two, every product of three. The lecture counts

$$1+\binom41+\binom42+\binom43=1+4+6+4=15,\qquad\text{and in general }\sum_{i=0}^{p}\binom di\;\approx\;d^{\,p}.$$

The lecture's rough figures: 10 features with relationships up to power 15 means on the order of $10^{15}$ mapped features, and 2 features up to power 20 on the order of $2^{20}$. The exact counts are smaller (see the note below), but the conclusion stands: for realistic numbers of features and powers, computing $\phi(x)$ explicitly becomes infeasible. L11 shows how to avoid computing it at all.

A counting note, going beyond the video. $\sum_{i\le p}\binom di$ counts products of distinct features ($f_1f_2f_3$). Allowing powers like $f_1^2f_2$ as well (the circle example needed $f_1^2$), the exact number of monomials of degree at most $p$ is $\binom{d+p}{p}$: 35 for 4 features up to cubic, about 3.3 million for $d=10,p=15$, and 231 for $d=2,p=20$. For a fixed power $p$ and many features this behaves like $d^p/p!$, a degree-$p$ polynomial in $d$, which is the sense in which it grows "like $d^p$". With $d=100$ and $p=5$ that's already about 96 million coordinates per point.

Key takeaways

  1. PCA only captures linear relationships. On a circle it needs both directions, though one exact rule ties the features together.
  2. A feature map $\phi$ of monomials turns a polynomial relationship into a linear one: $\phi(x_i)^\top u=0$ for all points.
  3. Recipe: map to $\mathbb R^D$, then run PCA there, using the $n\times n$ trick from L9 because $D$ is huge.
  4. Problem: $D\approx d^p$ explodes, so $\phi(x)$ may be too expensive (or impossible) to compute. Next: kernels.
