Lecture 45 · Classification: two ways to model

Generative and Discriminative Models

Learning only works if training and test data are linked. The link is an unknown but fixed distribution over (features, label) pairs. There are two schools for what to assume about it: a generative model describes how the features and the label are produced, $P(x,y)$; a discriminative model only describes the label given the features, $P(y\mid x)$.

Source: this lecture on YouTube (≈23 min). Previous: L44 · Next: L46.

1 · What links training and test data?

  • If the test points are exactly the training points, memorising wins, and nothing was learned.
  • If the test data is unrelated to the training data (study physics, get tested on chemistry), no algorithm can learn anything.
  • So we assume a middle ground: there is a distribution $D$ over $\mathcal X\times\mathcal Y$. Every training pair $(x_i,y_i)$ is drawn from $D$, and so is every test pair. Think of the box from the estimation lectures: press it, and out comes a point with its label.
  • The only assumption so far: $D$ is unknown but fixed. All we ever see of it is the training data.

2 · Two schools of modelling

To build a model we need more assumptions about $D$. A distribution over pairs means every (features, label) pair has a probability (a density, when features are continuous). The two schools differ in what they model:

Generative modelDiscriminative model
Models$P(x,y)$: features and label jointly$P(y\mid x)$: only the label given the features
Sayshow the features themselves are generatednothing about where $x$ comes from
Lecture's examplesomeone who speaks Bengali: can produce sentences, so recognising them is easysomeone who can only tell "Bengali or not" by ear, without speaking it
Which is better? There's no single answer. If you have good reason to believe how the features are generated (domain knowledge), generative modelling helps: knowing how to generate usually makes you better at discriminating. If you don't, a wrong generative story hurts even the discriminating task, so stick to discriminative.

3 · Where k-NN and decision trees fit

Both are discriminative: neither says anything about how $x$ is generated; each only says how to get $y$ once $x$ is given. Their "probabilities" are trivial, 0 or 1:

$$P(y=1\mid x)=\begin{cases}1 & \text{if the tree's leaf (or the majority of the $k$ neighbours) says 1}\\ 0 & \text{otherwise.}\end{cases}$$

Any deterministic rule from features to labels is a discriminative model in this sense. Probability just generalises a hard decision.

Key takeaways

  1. Training and test data are linked by one unknown, fixed distribution $D$ over (features, label). Without that link there is nothing to learn.
  2. Generative: model $P(x,y)$, including how features arise. Discriminative: model only $P(y\mid x)$.
  3. Use a generative model when you trust your story of how features are generated; otherwise go discriminative.
  4. k-NN and decision trees are discriminative, with 0/1 "probabilities".
