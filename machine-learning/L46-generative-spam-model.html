Lecture 46 · Classification: a first generative model

A Generative Model for Spam: The Dice Story

Turn each email into a 0/1 vector (is each dictionary word present?). Then tell a story for how (email, label) pairs are generated: toss a coin for the label, then roll that label's die, which has one face per possible email. It is a perfectly valid model, but it needs about $2^{d+1}$ numbers, far too many to learn. So the story must change.

Source: this lecture on YouTube (≈30 min). Previous: L45 · Next: L47.

1 · Emails as binary feature vectors

Data: $(x_1,y_1),\dots,(x_n,y_n)$ with $y_i\in\{0,1\}$ (1 = spam). Emails have different lengths, but algorithms need a fixed number $d$ of features. One simple way: let $d$ be the number of words in the dictionary, and set feature $j$ to 1 if word $j$ appears in the email, else 0.

Type an email

A toy dictionary of 12 words. A real one has $d\approx 10{,}000$, so the vector is mostly zeros. This is one simple encoding, not the only one, and it does reasonably well in practice.

2 · Which way to split $P(x,y)$

A generative model must give a probability to every (email, label) pair. The joint can be factored two ways:

$$P(x,y)=\underbrace{P(x)\,P(y\mid x)}_{\text{route A}}=\underbrace{P(y)\,P(x\mid y)}_{\text{route B}}$$
  • Route A already contains $P(y\mid x)$, which is all we need for prediction. If we can assume its structure, modelling $P(x)$ adds little: we may as well be discriminative.
  • Route B is the natural generative choice: $P(y)$ is how often spam occurs, and $P(x\mid y)$ is what spam emails look like and what non-spam emails look like. This is the route we take.

3 · The generative story: one coin, two dice

  1. Decide the label by tossing a coin: $P(y_i=1)=p$.
  2. Decide the features from $P(x_i\mid y_i)$: go to the room for that label and roll its die. The die has one face for each possible email, $2^d$ faces, each with its own probability.

The spam die and the non-spam die have the same faces but different probabilities: an email with "lottery, money" is likely to come off the spam die and unlikely (not impossible) off the other.

4 · Counting the parameters

  • The coin: 1 number, $p$.
  • Each die: $2^d$ face probabilities that must sum to 1, so $2^d-1$ free numbers.
$$\text{total}=1+2\,(2^d-1)=2^{d+1}-1 .$$

Knowing all of them means knowing the whole generating process, so we could compute $P(y\mid x)$ for any email. But to learn the model from data we'd have to estimate every one.

5 · The verdict

A generative story must pass two tests:

  1. Does it explain the data reasonably? Yes: it puts no restriction at all on what spam looks like.
  2. Can we learn it? No: with $d=10{,}000$ it has about $2^{10000}$ parameters.
Next: keep the coin (one parameter is fine), and replace the two enormous dice with something much smaller (L47).

Key takeaways

  1. An email becomes a $d$-dimensional 0/1 vector: feature $j$ = "does dictionary word $j$ appear?".
  2. Generative route: model $P(y)$ and $P(x\mid y)$, then $P(x,y)=P(y)P(x\mid y)$.
  3. Story: coin for the label, then a $2^d$-faced die for the email, with a different die per class.
  4. Parameters: $2^{d+1}-1$. Reasonable as a description, hopeless to learn. Change the story.
