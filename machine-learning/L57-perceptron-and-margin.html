Lecture 57 · Support vector machines: the motivation

Perceptrons and Margin

The perceptron's mistake bound $R^2/\gamma^2$ is governed by the best margin any separator achieves. Yet the separator the perceptron actually returns can have a tiny margin: it stops at the first line that makes no mistakes. A wide margin is worth having, because it tolerates noise in new data. So drop the perceptron and ask directly for the separator with the largest margin.

Source: this lecture on YouTube (≈19 min). Previous: L56 · Next: L58.

1 · Recall the bound

If $\lVert x_i\rVert\le R$ and some unit vector $w^*$ has $(w^{*\top}x_i)y_i\ge\gamma>0$ for all $i$, the perceptron makes at most $R^2/\gamma^2$ mistakes (L54). The gap $\gamma$ had to be non-zero, or the perceptron may never converge (L53).

2 · Many separators, different margins

A separable dataset usually has many valid $w^*$, each with its own margin. Say $w^*$ separates with $\gamma=10$ and another direction $w^*_2$ only with $\gamma=1$. Two observations:

  1. The number of mistakes depends on the best possible $w^*$'s margin. The proof only needed some $w^*$, so it holds for every one of them, and the largest margin gives the tightest bound: here at most $(R/10)^2$. A large best margin means an inherently easy problem.
  2. The perceptron's output need not be that best $w^*$. Nothing in the update rule aims for a wide margin. The moment the current $w$ makes no mistakes, the algorithm stops, even if that $w$ is the thin-margin $w^*_2$.

These don't contradict each other: an easy problem lets the perceptron find some separator quickly; it doesn't make it find the best one.

3 · Why prefer a wide margin

Suppose test data is a slightly noisy version of the training data: each point nudged a little. With a wide margin, a nudged point is still on the correct side. With a thin margin, points sit close to the line, and a small nudge carries them across. The margin is leeway: loosely, it buys generalisation.

4 · The new goal

Given that we prefer classifiers with a large margin, can we find the largest-margin one directly, in a principled way, instead of hoping an algorithm stumbles on it?

Key takeaways

  1. Different separating directions have different margins.
  2. The mistake bound uses the best margin; the perceptron's returned line can have a much smaller one.
  3. Wide margins tolerate noise: nearby test points stay on the right side.
  4. So aim for the maximum-margin separator directly.
