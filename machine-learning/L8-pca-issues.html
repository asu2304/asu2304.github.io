Lecture 8 · PCA in practice, and its limits

Eigenfaces, and Two Issues with PCA

Treat every face image as one long vector of pixels and run PCA: the principal components are themselves face-like images ("eigenfaces"), and a few hundred of them describe a 32,000-pixel face well enough to recognise the person. Then two concerns: computing the eigenvectors costs about $d^3$, painful when $d$ is huge; and PCA only finds linear structure, so data on a curved surface fools it. Surprisingly, one idea will fix both.

Source: this lecture on YouTube (≈25 min). Previous: L7 · Next: L9.

1 · Images as data points

The Extended Yale Face Database contains grayscale, same-size, camera-facing face images (the lecture quotes around 20,000 of them). To turn an image into features:

  • An image is an $m\times n$ matrix of pixels, each a grayscale value between 0 and 255.
  • Vectorise it into an $mn\times1$ vector. Here that's roughly 32,000 pixels, so every face is a point in $\mathbb R^{\approx 32{,}000}$.
  • Run standard PCA: the covariance matrix is $d\times d$ (about $32{,}000\times32{,}000$), and each eigenvector is also a 32,000-dimensional vector.
  • The pixel ordering is fixed, so the map can be reversed: reshape each eigenvector into an $m\times n$ image and look at it.

2 · What the principal components look like

  • PC1 is the direction of most variance in a dataset full of faces. As an image it's a prototype that captures the "faceness" of the data.
  • Later components add more and more detail: by some PC $k$, the nose and mouth are much sharper. The most common template comes first; other important characteristics follow.

3 · How many components does a face need?

Reconstruct a test face (not in the dataset, e.g. someone walking past a CCTV camera) from its projections on the top $r$ components: take its dot product with each component and linearly combine the component images with those coefficients.

Components keptTest face from the lecture's slides
25Clearly a person, but not clearly this person.
≈200–400The person-specific details are there: enough to recognise them.
1,600Close to the original, with finer details not needed for recognition.

So roughly 300 numbers instead of 32,000 pixels: about a 100× saving.

A dog's face, run through the same face components, comes out as "the best human representation of a dog" at 25, 100, 200 or 400 components. Only around 1,600 does it look like the dog. The top components are the important directions for human faces. Even 25 components separate "human" from "dog", while about 200–300 are needed to tell which human. A tree would need more (the lecturer's guess), and an image of random pixels has no structure at all, so reproducing it exactly needs all ~32,000 dimensions (with all of them, any image can be reconstructed).

Why it works: natural images like faces have structure. Most of their information lies in a low-dimensional linear subspace. In practice PCA is a pre-processing step: store each image's projections on the top few eigen-directions, train a supervised model on those, and project new test images the same way.

Computing the principal components…

Going beyond the video. Earlier lectures centre the data before PCA, and the demo does too by default: the mean face is subtracted, and $r=0$ reconstructs every image as the mean face. Untick the box to run PCA on raw pixels: then PC1 itself comes out close to the average face, the "faceness" template the lecture describes. The demo finds the top 32 components by orthogonal (subspace) iteration rather than a full $256\times256$ eigendecomposition.

4 · Issue 1: time complexity

The expensive step of PCA is finding the eigenvectors and eigenvalues of the $d\times d$ covariance matrix. Specialised numerical solvers exist, but a general rule is

$$\text{time}\;\approx\;O(d^3).$$

When $d$ is in the tens of thousands or millions this is a problem. In eigenfaces, $d\approx32{,}000$, larger than the number of images. Keep in mind that the number of data points was smaller than the number of features; L9 uses exactly that.

5 · Issue 2: non-linear structure

PCA searches for linear combinations of features: maybe weight + height, or 2·weight + 3·height. But features can be related non-linearly. Body mass index depends on weight divided by height squared; another dataset might have $f_3=f_1f_2+f_2^2$.

  • Then the data lies on a curved surface (a manifold, like a curved blanket) inside $\mathbb R^3$. Its true structure is 2-dimensional, just not flat.
  • PCA still returns an answer, the best plane, but the error relative to that plane stays large. It looks as though a third dimension matters, and with all 3 the error is 0, as it is for any dataset.
  • PCA never discovers that the data is essentially 2-dimensional. The problem: data may lie in a low-dimensional space, but not a low-dimensional linear subspace.

6 · One fix for both

The two issues look unrelated: one is about running time, the other about what structure PCA can find. The punchline of the lecture is that the same idea solves both. Solve issue 1 cleverly and the solution can be reused to solve issue 2. That begins in L9.

Key takeaways

  1. Images become vectors by flattening pixels; PCA's eigenvectors can be reshaped back into images ("eigenfaces").
  2. PC1 captures the common face template; later components add detail.
  3. A few hundred components recognise a face out of ~32,000 pixels. Images unlike the training data (a dog, random noise) need many more.
  4. Issue 1: eigendecomposition of the $d\times d$ covariance costs about $O(d^3)$, too slow for huge $d$.
  5. Issue 2: PCA finds only linear subspaces; non-linearly related features put data on curved surfaces that PCA misreads.
  6. One idea will fix both (L9 onwards).
