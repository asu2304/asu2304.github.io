14. Gradient boosting for binary classification: boost the log-odds

In binary classification, the training dataset contains a feature matrix and binary labels:

  • $X$: the input features (columns) for each observation.
  • $y$: the actual class label, with $y_i \in \{0, 1\}$.

The model does not directly build trees that output class labels. Instead, it builds an additive real-valued score (logit) and converts that score into a probability using the sigmoid function.

14.1 The model's score is a logit

Let the current model score be $F(x)$. Interpret it as the log-odds of the positive class:

$$F(x)=\log\frac{p(x)}{1-p(x)}$$

The corresponding probability is:

$$p(x)=\sigma(F(x))=\frac{1}{1+e^{-F(x)}}$$

The sigmoid converts any real-valued score into a number between 0 and 1.

  • $F(x) = 0$ gives $p(x) = 0.5$.
  • A positive score gives a probability above 0.5.
  • A negative score gives a probability below 0.5.

The final class can be chosen by thresholding the probability, commonly at 0.5. Equivalently, with that threshold, predict class 1 when $F(x) > 0$.

14.2 How this differs from logistic regression

In ordinary logistic regression, the score is linear in the features:

$$F(x)=w^\top x+b$$

In gradient-boosted trees, the score is an additive collection of tree outputs:

$$F_M(x)=F_0(x)+\eta\sum_{m=1}^{M}f_m(x)$$

Each tree contributes a piecewise-constant correction. The resulting decision boundary can therefore be nonlinear and can represent feature interactions.

14.3 The loss function

For binary labels $y \in {0,1}$, use binary cross-entropy (logistic loss):

$$\ell(y,F)=-\left[y\log p+(1-y)\log(1-p)\right], \qquad p=\sigma(F)$$

For a positive example ($y=1$), the loss is $-\log(p)$: a small predicted probability is penalized.

For a negative example ($y=0$), the loss is $-\log(1-p)$: a large predicted probability is penalized.

The loss is evaluated using the actual label and the model's current predicted probability. We do not need a target logit or a target probability in the training data; the given binary label is enough.

14.4 Gradient and Hessian with respect to the score

Differentiate the loss with respect to the model score $F_i$ (holding the actual label $y_i$ fixed):

$$g_i=\frac{\partial\ell(y_i,F_i)}{\partial F_i}=p_i-y_i$$

The second derivative, or Hessian for this one-dimensional score, is:

$$h_i=\frac{\partial^2\ell(y_i,F_i)}{\partial F_i^2} =p_i(1-p_i)$$

The negative gradient is the pseudo-residual:

$$r_i=-g_i=y_i-p_i$$

Interpretation:

  • If $y_i=1$, then $r_i=1-p_i$, which is nonnegative. The score should generally move upwards.
  • If $y_i=0$, then $r_i=-p_i$, which is nonpositive. The score should generally move downwards.

The label supplies the direction of correction; the current model probability determines how large the gradient is. We do not know a “correct logit” for each observation, and we do not need one. We differentiate the classification loss evaluated at the current score.

Because $y_i$ is either 0 or 1 and $p_i$ lies between 0 and 1, the magnitude of $y_i-p_i$ is at most 1. This is one reason logistic-loss boosting is less dominated by extremely misclassified observations than boosting with exponential loss. It does not make logistic boosting immune to label noise.

15. Initialization: where the first score comes from

Before fitting any tree, the model starts as a constant function:

$$F_0(x)=c\quad\text{for every observation }x$$

We choose the constant that minimizes total binary cross-entropy on the training labels:

$$c=\arg\min_c\sum_{i=1}^{n}\ell(y_i,c)$$

The derivative with respect to $c$ is:

$$\frac{dL}{dc}=\sum_{i=1}^{n}(\sigma(c)-y_i)$$

Set it to zero:

$$n\sigma(c)=\sum_i y_i$$

Therefore:

$$\sigma(c)=\bar y$$

where $\bar y$ is the fraction of positive examples in the training data. Applying the inverse sigmoid gives:

$$\boxed{F_0=\log\frac{\bar y}{1-\bar y}}$$

Example: 30% positive labels

If 30 out of 100 training observations have label 1, then:

$$\bar y=0.3,\qquad F_0=\log\frac{0.3}{0.7}\approx-0.847$$

The initial model assigns the same score $-0.847$ and probability $0.3$ to every observation. No feature has been used yet and no tree has been fitted.

Important: the fraction is calculated from the actual labels already present in the training dataset. It is not calculated from predicted labels. The initial constant probability is the model's starting prediction.

If the training set contains only one class, the unregularized log-odds would be infinite; practical implementations need safeguards for such edge cases.

16. What happens after initialization? A complete first-round walkthrough

Suppose we have four observations:

Observation Feature $x$ Actual label $y$
A 10 1
B 20 1
C 30 0
D 40 0

There are two positive labels out of four, so:

$$\bar y=0.5,\qquad F_0=\log\frac{0.5}{0.5}=0$$

Every observation initially has score 0 and probability:

$$p_i=\sigma(0)=0.5$$

Now calculate the gradients and negative gradients:

Point Actual $y_i$ Current $p_i$ Gradient $g_i=p_i-y_i$ Negative gradient $r_i=y_i-p_i$
A 1 0.5 -0.5 +0.5
B 1 0.5 -0.5 +0.5
C 0 0.5 +0.5 -0.5
D 0 0.5 +0.5 -0.5

The negative gradient tells us the direction in which each current score should move to reduce the loss locally:

  • A and B need their scores increased.
  • C and D need their scores decreased.

We now fit a regression tree using the feature values as inputs and the negative gradients as numerical targets:

$$\boxed{\text{Fit tree on }(X,r),\quad r_i=y_i-p_i}$$

The tree is learning a feature-dependent correction. It is not being fitted to the original binary labels in this boosting round, and it is not being fitted to the Hessians.

For the simple example, a split at $x = 25$ would put A and B in one leaf and C and D in another. This is just an illustrative split; an actual tree chooses splits by evaluating the available feature thresholds and their reduction in squared error on the pseudo-residual targets.

The order of operations

  1. Use the current ensemble to calculate scores $F_i$.
  2. Convert scores into probabilities $p_i = \sigma(F_i)$.
  3. Calculate gradients $g_i = p_i-y_i$ and Hessians $h_i=p_i(1-p_i)$.
  4. Fit a regression tree to features $X$ and negative gradients $r_i=-g_i$.
  5. Once the tree structure and its leaves are determined, calculate a Newton correction for each leaf using the gradients and Hessians of observations in that leaf.
  6. Add the shrunken leaf correction to the current model.
  7. Recalculate probabilities and gradients from the updated ensemble at the next round.

This ordering is important: in the basic GBDT procedure described here, the negative gradients determine the regression-tree fitting targets and SSE-based splits; the Hessians are used afterwards to calculate the Newton leaf values.

17. Newton leaf values: why divide by the sum of Hessians?

A fitted tree determines which observations share a leaf. It does not yet determine the final numerical correction to the model score for that leaf.

For a leaf $j$, let $I_j$ be its observations. We want a shared score correction $w$ that reduces the sum of logistic losses in that leaf:

$$L_j(w)=\sum_{i\in I_j}\ell(y_i,F_{m-1}(x_i)+w)$$

There is generally no simple closed-form solution for the exact minimizer. Instead, approximate each loss around $w=0$ with a second-order Taylor expansion:

$$\ell(y_i,F_i+w)\approx \ell(y_i,F_i)+g_iw+\frac12h_iw^2$$

Summing over the leaf and dropping terms that do not depend on $w$ gives:

$$L_j(w)\approx G_jw+\frac12H_jw^2$$

where:

$$G_j=\sum_{i\in I_j}g_i,\qquad H_j=\sum_{i\in I_j}h_i$$

Differentiate with respect to $w$ and set the derivative to zero:

$$G_j+H_jw=0$$

Thus the Newton leaf value is:

$$\boxed{w_j=-\frac{G_j}{H_j}}$$

Substituting the logistic gradient and Hessian:

$$\boxed{ w_j=\frac{\sum_{i\in I_j}(y_i-p_i)} {\sum_{i\in I_j}p_i(1-p_i)} }$$

What numerator and denominator mean

The numerator is the sum of negative gradients (the total requested correction) in the leaf.

The denominator is the sum of local curvatures of the loss with respect to the scores. Newton's method uses curvature to scale the step:

  • A larger Hessian sum means greater local curvature, so the Newton correction is smaller for the same gradient sum.
  • A smaller Hessian sum means lower local curvature, so the Newton correction can be larger.

The gradient measures the local slope; the Hessian measures how quickly that slope changes. The Hessian is also with respect to the model score/logit $F_i$, with the actual label held fixed.

Numerical example

Consider a leaf with two positive observations:

Point $y_i$ $p_i$ $y_i-p_i$ $h_i=p_i(1-p_i)$
A 1 0.9 0.1 0.09
B 1 0.8 0.2 0.16
Sum 0.3 0.25

The Newton leaf value is:

$$w_j=\frac{0.1+0.2}{0.09+0.16}=\frac{0.3}{0.25}=1.2$$

The denominator is $0.25$ because it is the sum of the two Hessians, not the number of observations. With learning rate $\eta=0.1$, the actual score update contributed by this leaf is $0.1 \times 1.2 = 0.12$.

Why this is not the average pseudo-residual

For squared loss:

$$\ell(y,F)=\frac12(y-F)^2,\quad g_i=F_i-y_i,\quad h_i=1$$

The Newton leaf value becomes:

$$w_j=-\frac{\sum_i g_i}{\sum_i h_i} =\frac{\sum_i(y_i-F_i)}{|I_j|}$$

That is exactly the mean residual. The reason is that every squared-loss Hessian equals 1, so the sum of Hessians is just the number of observations in the leaf.

For logistic loss, $h_i=p_i(1-p_i)$ varies with the current probability. Therefore, the denominator is generally not the number of observations, and the Newton leaf value is not simply the mean pseudo-residual.

A practical caution

When probabilities are very close to 0 or 1, $p_i(1-p_i)$ can be small. A leaf with a small total Hessian can therefore produce a large Newton step. Implementations control this with shrinkage, leaf constraints, limits on leaf values, or regularization.

With an L2 leaf penalty $\lambda$, the regularized Newton value becomes:

$$\boxed{w_j=-\frac{G_j}{H_j+\lambda}}$$

This is the form commonly encountered in XGBoost-style second-order tree learning.

18. How the new tree is combined with the existing model

After calculating the Newton value for each leaf, the new tree contributes a score correction. The model update is:

$$\boxed{F_m(x)=F_{m-1}(x)+\eta w_{j(x)}}$$

Here $j(x)$ is the leaf that contains $x$, and $\eta$ is the learning rate.

The new model is the previous ensemble plus the new tree's contribution. Then the updated ensemble is used to calculate the next round's probabilities and gradients:

$$p_i=\sigma(F_m(x_i))$$

This is the sequential nature of gradient boosting:

  • Round 1 uses the initial constant model to calculate gradients and fit tree 1.
  • Round 2 uses the combined model (initial constant plus tree 1) to calculate new gradients and fit tree 2.
  • Round 3 uses the constant plus trees 1 and 2 to calculate new gradients and fit tree 3.
  • This continues for the chosen number of rounds.

Unlike a Random Forest, where trees are trained independently and their predictions are aggregated, each boosting tree is trained in response to the current combined ensemble.

AdaBoost is also sequential and updates observation weights based on the current ensemble. The particular mechanism in gradient boosting is to calculate gradients of a chosen loss with respect to the current model predictions.

19. Complete binary-classification GBDT algorithm

Initialization

Calculate the positive-label fraction and set the initial score:

$$F_0=\log\frac{\bar y}{1-\bar y}$$

For rounds $m = 1, ..., M$:

  1. Calculate current probabilities:
$$p_i=\sigma(F_{m-1}(x_i))$$
  1. Calculate pseudo-residuals, gradients and Hessians:
$$r_i=y_i-p_i,\quad g_i=p_i-y_i,\quad h_i=p_i(1-p_i)$$

  1. Fit a regression tree to $(X, r)$ using the chosen tree-fitting procedure. In the basic method described here, split selection uses squared-error reduction on pseudo-residuals.

  2. For each leaf $j$, calculate its Newton value:

$$w_j=\frac{\sum_{i\in I_j}(y_i-p_i)} {\sum_{i\in I_j}p_i(1-p_i)}$$

With L2 regularization, add $\lambda$ to the denominator.

  1. Update the ensemble:
$$F_m(x)=F_{m-1}(x)+\eta w_{j(x)}$$

Prediction:

$$p(x)=\sigma(F_M(x))$$

Predict class 1 if $p(x)$ exceeds the chosen threshold (0.5 is common, but the threshold can be changed to suit the task).

20. Multiclass extension

For $K$ classes, maintain $K$ score functions:

$$F^{(1)}(x),F^{(2)}(x),\ldots,F^{(K)}(x)$$

Convert the scores into class probabilities using softmax:

$$p^{(k)}(x)=\frac{e^{F^{(k)}(x)}}{\sum_{l=1}^{K}e^{F^{(l)}(x)}}$$

For observation $i$, define the one-hot target for class $k$:

$$y_i^{(k)}=\begin{cases} 1 & \text{if observation }i\text{ belongs to class }k\\ 0 & \text{otherwise} \end{cases}$$

The negative gradient for class $k$ has the form:

$$r_i^{(k)}=y_i^{(k)}-p_i^{(k)}$$

A boosting round fits one tree for each class score, so there are $K$ trees per round in this formulation. This requires substantially more work than the binary case as the number of classes increases.

21. Hyperparameters: how they affect bias and variance

The bias–variance perspective helps explain the main controls. Boosting often begins with a simple, high-bias model and reduces training error as trees are added. But additional flexibility can eventually fit noise, causing generalization performance to deteriorate.

Hyperparameter What it controls General effect of increasing it
Number of rounds $M$ Number of trees added Usually reduces training error and bias initially; too many rounds can overfit. Use validation-based early stopping.
Learning rate $\eta$ Fraction of each tree's correction that is added A larger value makes each update more aggressive and can reach overfitting sooner. A smaller value usually requires more rounds and often gives smoother training.
Tree depth $d$ (or number of leaves) Complexity of each tree Deeper trees can model more complex patterns and interactions, reducing bias but increasing variance.
Minimum points per leaf Minimum number of observations allowed in a leaf A larger minimum makes leaves less specific and generally reduces variance.
Minimum Hessian per leaf Minimum sum of second derivatives allowed in a leaf Prevents leaves with very little curvature/support from receiving unstable Newton updates.
Row subsampling Fraction of training rows used by each tree A lower fraction adds randomness and can reduce correlation/variance; very small samples can increase bias.
Column subsampling Fraction/subset of features considered Adds randomness and can reduce correlation between trees; too few features can weaken individual trees.

21.1 Number of rounds

More rounds give the ensemble more opportunities to correct the current model. Training loss generally continues to improve, but validation loss may eventually stop improving and then worsen.

21.2 Learning rate

The update is:

$$F_m(x)=F_{m-1}(x)+\eta f_m(x)$$

If a tree proposes a correction of 2, a learning rate of 1 adds 2, while a learning rate of 0.1 adds 0.2. Smaller learning rates make the process more gradual and generally require more trees.

A smaller learning rate combined with more rounds often generalizes well and can make performance less sensitive to the exact stopping round. It is not a guarantee; the learning rate and number of rounds must be tuned together.

21.3 Tree depth and interaction order

Depth controls which feature relationships an individual tree can express.

  • Depth 1 (stumps): each tree splits on one feature. A sum of such trees is an additive model of one-variable functions, with no feature interactions:
$$F(x)=\sum_k f_k(x_k)$$
  • Depth 2: a tree can make a second split conditional on the first. It can represent a pairwise interaction, such as “if $x1$ is large and $x2$ is small”.
  • Greater depth: allows more complex conditional patterns and higher-order interactions.

Thus, depth is not merely a tree-size setting. It changes the kinds of relationships the ensemble can represent.

21.4 Minimum leaf size

A very small leaf can fit a small number of observations, potentially memorizing noise. Requiring more observations per leaf makes the tree's predictions less specific and usually reduces variance.

21.5 Row and column subsampling

Row subsampling selects a random subset of observations for a tree. Column subsampling selects a random subset of features for a tree or split. Both introduce randomness and can reduce correlation between successive trees, acting as regularization.

22. Stochastic Gradient Boosting: bagging-like randomness inside boosting

Stochastic Gradient Boosting, associated with Friedman's 2002 work, adds row subsampling to each boosting round.

Instead of fitting every tree using all training rows, randomly sample a fraction $s$ of the rows without replacement. A common illustrative range is around 50–80%, though the suitable value depends on the dataset and implementation.

22.1 Why subsample rows?

Variance reduction: consecutive trees see different subsets, so their fitted structures are less dependent on exactly the same observations. This can reduce correlation between trees and help control variance.

Regularization: an individual noisy observation does not influence every tree's fit.

Speed: if a tree uses a fraction $s$ of the rows, its fitting work can be reduced accordingly (the exact speed-up depends on the implementation and other costs).

22.2 An important implementation detail

The pseudo-residuals are calculated from the full current ensemble. Then a random subset is selected for fitting the next tree. The tree structure and its leaf values are fitted/calculated using the selected subsample in the procedure described here.

So the distinction is:

  • The current model supplies predictions and gradients for the training observations.
  • Only the selected rows are used to fit that round's tree and estimate its leaf corrections.

Column subsampling applies the same broad idea to features rather than observations.

22.3 Connection to Random Forest

Both Random Forest and stochastic gradient boosting use sampling to introduce randomness, but their overall learning procedures remain different:

  • Random Forest trains trees independently and aggregates their predictions.
  • Stochastic Gradient Boosting still trains trees sequentially; each new tree responds to the current ensemble's gradients, while using a random row subset for its fit.

LightGBM's GOSS (Gradient-based One-Side Sampling) is a more specialized sampling strategy. Rather than selecting rows uniformly at random, it gives special treatment to observations with larger gradient magnitudes.

23. Practical takeaways and conceptual checks

  1. The training labels are available from the beginning. They are not predicted labels. The initial positive fraction is calculated directly from the actual labels.
  2. The initial model is a constant score. It predicts the base-rate probability for every observation, without using features.
  3. There are no target logits. The binary label and the differentiable cross-entropy loss give the gradient with respect to the current logit.
  4. The tree is fitted to negative gradients. In this binary logistic-loss example, the pseudo-residual is $y_i-p_i$.
  5. The Hessian is not the tree's target. It is the second derivative of the loss with respect to the score and is used to scale the Newton leaf correction.
  6. The Newton leaf value is not generally the mean pseudo-residual. It is the sum of negative gradients divided by the sum of Hessians (with regularization where used).
  7. The tree is fitted before its Newton leaf values are assigned in the basic procedure described here: the gradient targets guide tree fitting; the gradient and Hessian sums then determine leaf outputs.
  8. The ensemble is updated after every tree. The next round's probabilities and gradients come from the combined model built so far.
  9. This sequential dependence is a key distinction from Random Forest. Random Forest trees are independently fitted; boosting trees are fitted in response to the current ensemble.
  10. Overfitting is possible. Additional rounds can fit noise after useful structure has been learned. Depth, learning rate, leaf constraints, subsampling, regularization and early stopping help control this.

Mental picture: Start with the best constant probability given by the training-label base rate. Evaluate the classification loss at the current model scores. Its negative gradients say which way the scores should move. Fit a regression tree to approximate those corrections from the features. Use the Hessians to scale each leaf's correction with a Newton step. Add the shrunken tree to the current ensemble, recalculate predictions, and repeat.
