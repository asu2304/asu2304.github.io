LightGBM: histogram construction, split evaluation, and leaf-wise growth

This file continues Gradient Boosting Revision Notes, Part 2. It focuses on the concepts we unpacked while learning LightGBM: second-order split evaluation, how numerical feature bins are constructed, how histograms are used to find splits, and how leaf-wise growth builds a complete tree.

1. Where LightGBM fits

Gradient Boosting is the general procedure: build an additive model sequentially, with each new tree correcting the current ensemble. LightGBM is an efficient implementation of gradient-boosted decision trees. It retains the boosting idea but changes parts of tree construction to reduce computation and memory use.

The topics covered here are second-order split evaluation, histogram-based split finding, and leaf-wise (best-first) tree growth. GOSS and EFB are further LightGBM optimizations and are not covered here.

2. Second-order split evaluation

At a boosting round, suppose the current ensemble gives observation $i$ the score $F_i$. A candidate leaf assigns a shared score correction $w$ to every observation in that leaf.

Approximate each observation's loss around its current score with a second-order Taylor expansion:

$$\ell(y_i,F_i+w)\approx \ell(y_i,F_i)+g_iw+\frac12h_iw^2,$$

where

$$g_i=\frac{\partial \ell(y_i,F_i)}{\partial F_i}, \qquad h_i=\frac{\partial^2 \ell(y_i,F_i)}{\partial F_i^2}.$$

This quadratic approximation matches the loss's value, slope and curvature at the current score. It is local; it is not the exact loss curve everywhere.

For observations $I$ in one leaf, define

$$G_I=\sum_{i\in I}g_i,\qquad H_I=\sum_{i\in I}h_i.$$

Including L2 regularization $\lambda$, and dropping terms independent of $w$, the approximate objective is

$$Q_I(w)=G_Iw+\frac12(H_I+\lambda)w^2.$$

Differentiating and setting to zero gives

$$\boxed{w_I^*=-\frac{G_I}{H_I+\lambda}}.$$

Substituting this value into the quadratic gives the estimated improvement from giving this set its own optimal leaf correction:

$$\boxed{\operatorname{Score}(I)=\frac12\frac{G_I^2}{H_I+\lambda}}.$$

Why evaluate a split?

Before splitting, every observation in a parent leaf shares one correction. After splitting, the left and right children can receive different corrections.

For parent $P$ and children $L,R$, the estimated gain is

$$\boxed{ \operatorname{Gain} = \frac12\left[ \frac{G_L^2}{H_L+\lambda} + \frac{G_R^2}{H_R+\lambda} - \frac{G_P^2}{H_P+\lambda} \right]-\gamma }$$

where $\gamma$ penalizes adding a split.

In words:

$$\text{split gain} = \text{best child scores} - \text{best parent score} - \text{split penalty}.$$

A positive gain means that, under the local quadratic approximation and regularization settings, allowing the two groups to have separate corrections is worthwhile.

The algorithm is choosing a partition of observations. The split determines which observations receive which leaf correction; it is not directly choosing a movement in parameter space.

Numerical example

Suppose

$$G_P=10,\ H_P=20,\quad G_L=15,\ H_L=12,\quad G_R=-5,\ H_R=8$$

and $\lambda=\gamma=0$. Then

$$\begin{aligned} \operatorname{Gain} &=\frac12\left[ \frac{15^2}{12} +\frac{(-5)^2}{8} -\frac{10^2}{20} \right]\\ &=\frac12(18.75+3.125-5)\\ &=8.4375. \end{aligned}$$

The positive gain says that this split gives a better approximate objective than keeping the parent as one leaf.

3. Why use both gradients and Hessians?

The gradient gives the local slope: which direction decreases the loss and how steeply it is changing. The Hessian gives local curvature: how quickly the slope changes. A Newton correction uses both:

$$w^*=-\frac{G}{H+\lambda}.$$

Using only the gradient gives a direction, but not the curvature-aware Newton step size. A first-order method is possible, but it needs a step-size choice or line search.

For binary logistic loss,

$$p_i=\sigma(F_i),\qquad g_i=p_i-y_i,\qquad h_i=p_i(1-p_i).$$

Both $G$ and $H$ therefore depend on the current ensemble predictions.

4. Why ordinary split search can be expensive

For one numerical feature in a leaf, conventional exact split search sorts the feature values and considers thresholds between successive distinct values. At each threshold, it needs the gradient and Hessian sums on both sides:

$$G_L,\ H_L,\ G_R,\ H_R.$$

These sums can be accumulated while scanning sorted observations, but repeating this for many observations and features is expensive.

LightGBM reduces the number of candidate thresholds by grouping feature values into a limited number of bins.

5. How LightGBM creates the bins

The bins are not chosen using gradients, Hessians, labels, or split gains. For a numerical feature, LightGBM looks at the distribution of that feature's observed values and constructs data-driven intervals using an approximate quantile-style strategy.

The aim is generally for bins to contain roughly similar numbers of observations, rather than having equal-width intervals.

For example, suppose a feature has sorted values

$$1.2,\ 1.5,\ 2.1,\ 2.4,\ 3.0,\ 3.2,\ 4.8,\ 5.1,\ 7.0,\ 9.0.$$

Four illustrative bins might group the first two values, the next two, the next four, and the final two. This only illustrates the idea; it is not a claim about the exact boundaries LightGBM would choose.

So the right core intuition is approximately equal-frequency bins, not equal-width bins. With 10,000 observations and a target of around 100 bins, a rough mental picture is about 100 observations per bin.

The actual procedure is approximate and subject to constraints:

  • max_bin limits the number of bins for a feature.
  • min_data_in_bin discourages bins containing too few observations.
  • LightGBM uses an efficient bin-construction procedure and can use sampling, rather than requiring an expensive exact sort of every training value.
  • Missing values and categorical features have their own handling; they should not be thought of as ordinary continuous values placed into numeric intervals.

The bin mapping for a feature is constructed as part of dataset preparation and reused during tree training. It is not normally rebuilt from scratch for every candidate split.

6. Once bins exist, how does histogram split finding work?

The expensive search over individual observations becomes a search over bin boundaries.

For a particular feature and current leaf:

  1. Each observation already has a bin index for that feature.
  2. Add its gradient and Hessian to the totals for that bin.
  3. Each bin $b$ now has $G_b=\sum_{i\in b}g_i$ and $H_b=\sum_{i\in b}h_i$.
  4. Scan bins in increasing feature-value order. Prefix sums give the left-side totals at boundary $k$: $G_L=\sum_{b\le k}G_b$ and $H_L=\sum_{b\le k}H_b$.
  5. Obtain the right-side totals by subtracting from the parent totals: $G_R=G_P-G_L$ and $H_R=H_P-H_L$.
  6. Evaluate the second-order gain at each valid bin boundary and choose the best one.

The candidate thresholds are therefore bin boundaries, not every distinct raw feature value.

If a leaf contains thousands of observations but a feature has at most 255 bins, split evaluation scans at most about 255 bin boundaries rather than thousands of individual thresholds. The trade-off is reduced threshold resolution: a threshold inside a bin is not separately considered.

Keep these two ideas separate

  • Second-order gain tells us how to score a candidate split using $G$ and $H$.
  • Histogram binning reduces the number of candidate thresholds that must be scored.

The gain formula does not create the bins. Binning is an efficiency technique for split search.

7. Does LightGBM build a decision stump at every step?

No. A stump has exactly one split and two leaves. LightGBM generally grows a multi-leaf decision tree during each boosting iteration.

Keep the levels separate:

  • One split divides one current leaf into two children.
  • One tree may contain many splits and leaves.
  • One boosting iteration adds one newly grown tree to the existing ensemble.

LightGBM can make several splits while constructing the same tree. It does not stop after the first split unless the tree constraints allow only a stump. The final boosted model is an additive ensemble of these trees.

8. Leaf-wise growth: which leaf is split next?

A level-wise strategy expands nodes at the same depth together. For example, it may split every eligible node at depth 1 before splitting nodes at depth 2.

LightGBM's characteristic strategy is leaf-wise, also called best-first growth:

  • Find the best available split and gain for every current leaf.
  • Compare those gains across leaves.
  • Split the leaf with the largest gain, even if it is at a different depth from other leaves.
  • Repeat, subject to stopping conditions.

For example, if leaf A has best gain 8 and leaf B has best gain 3, LightGBM chooses A next.

Why this is greedy budget allocation

Every split turns one leaf into two and therefore spends some of the tree's complexity budget. Leaf-wise growth greedily spends the next unit of budget on the currently available split with the largest gain.

This can reduce training loss quickly for a fixed leaf budget, but it is greedy and does not guarantee the globally optimal tree. Since it follows gain rather than depth, the resulting tree can be unbalanced and can grow deep along some branches.

Controls include:

  • num_leaves: limits the number of leaves;
  • max_depth: limits depth;
  • min_data_in_leaf: requires a minimum number of observations in a leaf;
  • min_sum_hessian_in_leaf: requires sufficient summed Hessian in a leaf.

9. The complete mental picture

At a boosting round, the current ensemble produces scores. From those scores and labels, calculate gradients and Hessians.

For a candidate tree, LightGBM uses a second-order approximation to estimate how much a split could improve the objective. To make the search efficient, each numerical feature has already been mapped into a limited number of bins. The algorithm aggregates gradient and Hessian sums in those bins, scans bin boundaries, and evaluates their gains.

It grows one tree by repeatedly splitting the current leaf with the largest available gain. Once the tree is complete, its leaf corrections are added to the ensemble with shrinkage, and the next boosting round begins.

$$\boxed{ \text{Current ensemble} \rightarrow (g_i,h_i) \rightarrow \text{histogram split search} \rightarrow \text{leaf-wise tree} \rightarrow \text{ensemble update} }$$

10. Quick self-check

  • Why does a second-order approximation use both a gradient and a Hessian?
  • Why is split gain the children's improvement minus the parent's improvement?
  • Are numerical histogram bins chosen using gradients and Hessians? No; they are based on feature-value distributions.
  • Is the basic binning intuition approximately equal-frequency or equal-width? Approximately equal-frequency.
  • What does max_bin control? The maximum number of bins for a feature.
  • What is accumulated in each bin during a boosting round? Gradient and Hessian sums.
  • Why scan bin boundaries instead of every raw value? There are fewer candidate thresholds.
  • Does one boosting iteration build only a stump? No; it generally builds a multi-split tree.
  • What does leaf-wise growth choose greedily? The current leaf whose best available split has the largest gain.
  • Why can leaf-wise growth need regularization? It can create deep, unbalanced trees and overfit.
