Why OOP? Classes and Objects

In Python everything is an object, and every object belongs to a class: the class is the blueprint that says what data an object holds and which methods it can call. The core promise of object-oriented programming is that you can write your own classes, that is, build your own data types shaped exactly like the problem you are solving.

2 · The problem: big, real-world code ▶ 3:27

Around 2010, most of daily life was offline: going to the bank, booking train and movie tickets, choosing a hotel by physically visiting it. Fast-forward (and add a pandemic) and nearly everything is online. That happened because people picked a piece of real life and turned it into software: OYO (Ritesh Agarwal) put hotel photos online so you no longer inspect rooms in person, cab apps track you by GPS instead of you waiting on the roadside, photo-sharing apps replaced passing albums around.

His own story. After college he built a LinkedIn-like platform for college students: login, profile pages, messaging and many more features. It took six to eight months, and by then the code was so large that adding any new feature confused him, because he had written it in the "normal" (procedural) style. He rewrote it with OOP, and redid roughly that much work in about two months. OOP pays off precisely when you build a real application with lots of code.

3 · The core idea: from generality to specificity ▶ 6:44

His one-line definition of OOP's most fundamental feature: you can make your own data types. If you are building LinkedIn, you can build LinkedIn-shaped data, instead of forcing everything into the general-purpose types (int, str, list, tuple, dict).

The Kali Linux analogy ▶ 7:40. Kali is an operating system made specifically for penetration testing (hacking): the tools come pre-installed and configured. You can hack from Windows, but a specialised tool makes you better at the specialised job. Same with code: you can build LinkedIn from general data types, but a data type made specifically for it serves you better.

Add the other ideas you have probably heard of, encapsulation, polymorphism, inheritance, and you get object-oriented programming: a different technique of writing code, well suited to real applications that solve real problems.

5 · Class: the blueprint ▶ 10:30

First rule to remember: an object is always an object of some class. In real life too: this Dell mouse is an object of the class "mouse"; you are an object of the class "human"; India is an object of the class "country". So if everything in Python is an object, the question is: of which class? Ask Python ▶ 11:37:

a = 2
L = [1, 2, 3]
s = "hello"
print(type(a))
print(type(L))
print(type(s))
<class 'int'>
<class 'list'>
<class 'str'>

Focus on the word class. Somebody wrote the list data type, and "writing a data type" means defining its class: its blueprint. Type L. and press Tab, and you see a column of functions (append, pop, …). Whoever created list put those functions inside the class, and only a list object can use them. Rename the variable to an integer and those functions vanish; a different set, for integers, appears.

In simple words (literally true in Python): a data type is a class, and a variable of that data type is an object. L is an object of class list.

Which takes more code to make, a class or an object? The class, by far. Its author writes the blueprint of how every list will behave, so they write all the functions. Making an object is one line: L = [1, 2, 3].

So: a class is a blueprint of how an object will behave.

6 · What lives inside a class: data and methods ▶ 14:23


A class contains exactly two kinds of things:




Data = properties = attributes
a description of the object: what it has


Functions = methods
the object's behaviour: what it does




His example is the classic car ▶ 15:05. Every car has some number of wheels, a colour, an engine type, a brand: that is its data. Every car can calculate its mileage, calculate its average speed, open an airbag, show GPS navigation: those are its methods. Every car has a colour, but each car has its own colour.

9 · Object: an instance of a class ▶ 19:49


The data type is the class; the variable you make from it is the object. An object is an instance of a class. If "car" is a class, a particular car is its object; if "sport" is a class, gilli-danda is an object; if "animal" is a class, a langur is an object. Creating one in Python:


objectname = ClassName()


class Car:
    pass

wagon_r = Car()
print(type(wagon_r))
