Building an ATM: Class, Object and Constructor

The theory clicks only when you build something, so he writes the software for an ATM machine as a class: two pieces of data (pin and balance) and a handful of methods. A method is a function defined inside a class. Whenever you see object.something(), that is a method. Everything we write inside Atm is a method. He asks you to say "method" in interviews, because saying "function" there sounds technically loose.

3 · Attributes are created inside __init__ ▶ 27:35

Unlike Java, where variables are declared directly in the class body, in Python you create the object's variables inside a special method called __init__, written as self.pin = '' and self.balance = 0. Every method also receives self as input. He promises to explain self shortly (that is part 3); for now, just write it.

4 · The constructor ▶ 29:20

__init__ is the constructor: a special method whose code runs automatically the moment you create an object of the class. Prove it ▶ 30:16:

class Atm:
    def __init__(self):
        print('hello')

sbi = Atm()
hdfc = Atm()
hello
hello

Nobody called __init__; creating each object triggered it. (He saves the class in a file in the working folder and imports it in the notebook with from xyz import Atm.)

Python vs other languages ▶ 31:27: in Java/C++ the constructor has the same name as the class. In Python it must always be named __init__, two underscores before and after. Misspell it and it is just an ordinary method that never runs automatically.

5 · The menu ▶ 32:02

The plan: as soon as an object is made, create the two variables, then call menu() from the constructor. The menu is a multi-line input() (triple quotes), the way old ATMs talked to you through numbers. The user's answer comes back as a string, so compare with '1', not 1.

6 · The full class ▶ 36:15

Each method follows the real ATM: ask for the pin, compare with self.pin, then act on self.balance. int() the amount, since input() returns a string. Withdraw ▶ 39:31 adds one more check: you can only take out what you have. Check balance ▶ 41:28 just prints it after the pin check.

class Atm:

    # constructor (special method / magic method)
    def __init__(self):
        self.pin = ''
        self.balance = 0
        self.menu()

    def menu(self):
        user_input = input("""
    Hello, how would you like to proceed?
    1. Enter 1 to create pin
    2. Enter 2 to deposit
    3. Enter 3 to withdraw
    4. Enter 4 to check balance
    5. Enter 5 to exit
    """)

        if user_input == '1':
            self.create_pin()
        elif user_input == '2':
            self.deposit()
        elif user_input == '3':
            self.withdraw()
        elif user_input == '4':
            self.check_balance()
        else:
            print('bye')

    def create_pin(self):
        self.pin = input('Enter your pin: ')
        print('Pin set successfully')

    def deposit(self):
        temp = input('Enter your pin: ')
        if temp == self.pin:
            amount = int(input('Enter the amount: '))
            self.balance = self.balance + amount
            print('Deposit successful')
        else:
            print('Invalid pin')

    def withdraw(self):
        temp = input('Enter your pin: ')
        if temp == self.pin:
            amount = int(input('Enter the amount: '))
            if amount < self.balance:
                self.balance = self.balance - amount
                print('Operation successful')
            else:
                print('Insufficient funds')
        else:
            print('Invalid pin')

    def check_balance(self):
        temp = input('Enter your pin: ')
        if temp == self.pin:
            print(self.balance)
        else:
            print('Invalid pin')

His aside on repetition ▶ 42:16: the pin check is copy-pasted three times. Better to write a separate method (say check_pin) and call it every time; the code becomes shorter and easier. He calls this "a very basic ATM", with room for more creativity.

Going beyond the video: amount < self.balance refuses to let you withdraw your entire balance (withdrawing exactly 25000 from 25000 says "Insufficient funds"). Use <= if emptying the account should be allowed.

8 · Magic (dunder) methods ▶ 47:54


Python has a set of special methods, also called magic methods or dunder methods ("double underscore"). The constructor is one of them; search "magic methods in Python" and you will find many more.


    

  • How to recognise one: double underscore before and after the name (__init__).
    • 

  • You cannot invent them. Renaming your menu to __menu__ does not make it magic; the set is predefined by Python.
    • 

  • Objects don't call them; they trigger automatically in a given situation. You call sbi.deposit() yourself, but the constructor fires on object creation.
    •

Going beyond the video: "can't call it" is true in spirit, not literally: sbi.__init__() runs (it would reset the pin and balance), and dir(sbi) does list __init__. Tab completion just hides underscore names by default. Treat it as a convention: never call dunders yourself.



9 · What is a constructor actually for? ▶ 51:13


Everyone can define a constructor; few can say when to use one. Think of the ATM as a real machine: there is a button for withdraw, a button for deposit, but no button for the constructor. Control over it is never given to the user.


Rule of thumb: put in the constructor the code that must run when the app starts and that you don't want to leave to the user: configuration. Connecting to the internet, to a database, to hardware such as GPS. You wouldn't add a "please connect to the internet" button and hope the user presses it. (Asking for GPS permission when a cab app opens is that kind of start-up code.)


A philosophical aside ▶ 54:26: if the world is a class, God the programmer and humans its objects, then what is in the constructor? The things outside our control. The moment you are born, one thing is already decided: you will die. In a very loose sense, that is how a constructor works.



Key takeaways


    

  1. Design a class by listing its data (ATM: pin, balance) and its methods (create pin, deposit, withdraw, check balance).
    2. 

  2. A method is a function defined inside a class and called on an object (L.append(4)); a function is general (len(L)).
    3. 

  3. In Python, instance variables are created inside __init__ as self.name = value.
    4. 

  4. The constructor __init__ runs automatically when an object is created; its name is fixed in Python.
    5. 

  5. Every object has its own copy of the data: sbi.balance and hdfc.balance are independent.
    6. 

  6. Magic/dunder methods are predefined, have double underscores on both sides, and fire automatically. Use the constructor for start-up configuration the user should not control.
