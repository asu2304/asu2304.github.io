What self Really Is

self is simply the object you are currently working with. When you write sbi.deposit(), Python quietly passes sbi into the method, and the method receives it as self. It is needed because, inside a class, methods and data can only be reached through an object, so each method needs the object in hand.

1 · The puzzle ▶ 56:01

In the ATM class the word self is everywhere: self.pin, self.balance, self.menu(), and every method takes self as input. What is it? He admits it is a slightly confusing idea, best understood with a small experiment.

2 · The experiment: print the address of self ▶ 56:45

The reasoning: self is something. Everything in Python is an object, so self is an object; every object lives somewhere in memory, so it has an address, which id() gives us. Print it inside the constructor, then compare with the address of the object we created:

class Atm:
    def __init__(self):
        print(id(self))
        self.pin = ''
        self.balance = 0

sbi = Atm()
print(id(sbi))
hdfc = Atm()

(Your numbers will differ; what matters is which ones are equal.) When sbi was being built, self had the same address as sbi. Make a second object hdfc ▶ 58:31 and self now has the address of hdfc, while id(sbi) is unchanged.

3 · The one-line answer ▶ 59:20

self is the object you are currently working with. While sbi is working, self is sbi; while hdfc is working, self is hdfc.

4 · Remove self and see what breaks ▶ 59:59


Why must every method receive self? Delete it from one method and call that method:


class Atm:
    def __init__(self):
        self.pin = ''
        self.balance = 0

    def create_pin():          # self removed!
        print('creating pin')

sbi = Atm()
sbi.create_pin()


TypeError: create_pin() takes 0 positional arguments but 1 was given


(Python 3.10+ words it as Atm.create_pin() takes 0 positional arguments but 1 was given.)


"But 1 was given"? We passed nothing! ▶ 1:02:20 That is the reveal: whenever you call object.method(), Python passes the object itself as the first input by default. When sbi called create_pin, the method received sbi, and that first parameter is what we name self.


Going beyond the video: you can do Python's rewrite yourself. sbi.show() is shorthand for Atm.show(sbi):

class Atm:
    def __init__(self):
        self.pin = '1234'
        self.balance = 500

    def show(self):
        print(self.balance)

sbi = Atm()
sbi.show()        # what you write
Atm.show(sbi)     # what Python does for you


500
500

And the name self is only a convention (any name works for the first parameter), but always use self.

6 · Revision ▶ 1:05:15


His recap: a class has data and methods; only its objects can use them; therefore a method cannot reach its sibling methods or data on its own, yet in many scenarios it must (like the constructor calling menu). It gets an object through self, which is whichever object called the method. The concept is not difficult, yet many students never really grasp it; once you understand it, you will stop making mistakes with self.



Key takeaways


    

  1. self is the current object: id(self) inside the method equals id(sbi) when sbi is the caller.
    2. 

  2. obj.method() automatically passes obj as the first argument; that parameter is named self.
    3. 

  3. Forget self in a method definition and calling it gives TypeError: … takes 0 positional arguments but 1 was given.
    4. 

  4. Members of a class are reachable only through an object, so even methods of the same class must go through self. to reach each other and the data.
    5. 

  5. Different objects, different self: that is how one deposit method updates the right balance.
