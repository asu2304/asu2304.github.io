Reference Variables and Pass by Reference

The variable you store an object in is not the object: it's a reference, holding the object's address. Pass it to a function and the function gets the same address, so a mutable object (a list, a dict, or any object of your own class) edited inside the function stays edited outside it.

Source: this part of the video on YouTube (1:49:20–2:11:40 of a 4-hour video). Previous: encapsulation · Next: collections of objects and static members.

Credit. These notes follow Nitish Singh's Complete OOP in Python video on his channel CampusX. The teaching, structure and examples are his; mistakes, and everything in the orange "going beyond" boxes, are mine.

1 · The variable is not the object ▶ 1:49:34

Import the Atm class and just write Atm(). An object really is created, at some location in memory. But can you use it? No: you didn't store it anywhere, so it's lost and you can never find it again.

class Atm:
    def __init__(self):
        self.pin = ''
        self.balance = 0

Atm()            # created... and immediately lost
sbi = Atm()      # sbi stores a reference to the new object
print(sbi)
<__main__.Atm object at 0x1058db4c0>

When you write sbi = Atm(), two things exist: the object, sitting at some address in memory, and the variable sbi, which stores that address (a reference to the object). We casually say "the object sbi", but sbi is not the object.

The variable in which you store an object when you create it is called a reference variable: it points to the object; it doesn't contain it.

2 · Passing your own objects to functions ▶ 1:51:23

A small Customer class, and a greet function written outside the class (so it's a function, not a method) that receives a customer:

class Customer:
    def __init__(self, name, gender):
        self.name = name
        self.gender = gender

def greet(customer):
    if customer.gender == 'Male':
        print('Hello', customer.name, 'sir')
    else:
        print('Hello', customer.name, "ma'am")

cust = Customer('Nitish', 'Male')
greet(cust)
cust2 = Customer('Ankita', 'Female')
greet(cust2)
Hello Nitish sir
Hello Ankita ma'am

Nothing new was really learned here, he says, and that's the point: if a function can take an integer, a string, a list or a dict, it can take an object of your class too, because in Python everything is an object. Inside the function, customer is that object, so customer.name and customer.gender work.

3 · Functions can return objects too ▶ 1:57:43

class Customer:
    def __init__(self, name, gender):
        self.name = name
        self.gender = gender

def greet(customer):
    if customer.gender == 'Male':
        print('Hello', customer.name, 'sir')
    else:
        print('Hello', customer.name, "ma'am")
    cust2 = Customer('Ankita', 'Female')
    return cust2

cust = Customer('Nitish', 'Male')
new_cust = greet(cust)
print(new_cust.name)
Hello Nitish sir
Ankita

The function built a new Customer and returned it; outside, new_cust receives it and, being an object, has a name (and a gender). Your own types behave like the built-in data types: they go into functions and come back out.

4 · Inside and outside: the same object? ▶ 1:59:23

Now it gets interesting. Print the id (the address) of the object outside, then inside the function. Same or different? Then change the name inside the function. What does cust.name print outside: Ankita or Nitish? Guess first.

class Customer:
    def __init__(self, name):
        self.name = name

def greet(customer):
    print(id(customer))
    customer.name = 'Nitish'
    print(customer.name)
    print(id(customer))

cust = Customer('Ankita')
print(id(cust))
greet(cust)
print(cust.name)
4305493776
4305493776
Nitish
4305493776
Nitish

The exact numbers differ on every run; what matters is that they're equal.

  1. Same id ▶ 2:01:20. You didn't send the object; you sent the reference. customer = cust happened, so both names point to one object. This is pass by reference.
  2. Nitish outside too ▶ 2:04:00. Both names point to the same object and you changed an attribute of that object, so the change is permanent and visible everywhere. If you pass an object to a function and the function edits it, your original object changes. Logical, once you picture the arrows.
  3. Same id after the edit ▶ 2:05:40. The object was edited in place; its address didn't change. That means objects of your own classes are mutable, just like lists, dictionaries and sets.

5 · The same story with a list ▶ 2:07:19

Someone asked how a list can be changed inside a function. Same reason: a list is mutable and the function gets a reference to it.

def change(L):
    print(id(L))
    L.append(5)
    print(id(L))

L1 = [1, 2, 3, 4]
print(id(L1))
print(L1)
change(L1)
print(L1)
4300240064
[1, 2, 3, 4]
4300240064
4300240064
[1, 2, 3, 4, 5]

The function's append permanently changed the list outside. Advice ▶ 2:09:36: if you don't want a function to mess with your original list, don't send the original. Send a clone; the function works on a separate list and yours is untouched:

def change(L):
    L.append(5)

L1 = [1, 2, 3, 4]
change(L1[:])        # send a copy (a clone)
print(L1)
[1, 2, 3, 4]

6 · Immutable data: the tuple ▶ 2:10:23

With a tuple there's no such worry, because tuples are immutable. append doesn't even exist; you have to write L = L + (5, 6), which builds a new tuple and points the local L at it:

def change(L):
    print(id(L))
    L = L + (5, 6)
    print(id(L))
    print(L)

L1 = (1, 2, 3, 4)
print(id(L1))
change(L1)
print(L1)
4424644144
4424644144
4424639296
(1, 2, 3, 4, 5, 6)
(1, 2, 3, 4)

Inside, the id changes after the operation (a new object); outside, the original tuple is untouched.

You pass…ExamplesCan the function change your original?
Mutable datalist, dict, set, objects of your classesYes, permanently. Be careful, or pass a copy.
Immutable dataint, float, str, tupleNo: "changes" create a new object inside the function.
Going beyond the video. Strictly, Python is neither classic pass-by-reference nor pass-by-value; it's often called pass by object reference (or pass by assignment): the parameter is a new name bound to the same object. That's why mutating (L.append, customer.name = …) is visible outside, but rebinding (L = L + …, or customer = Customer(…)) never is, even for a list. Plain assignment does the same thing, which is called aliasing: 
p = [1, 2]
q = p
q.append(3)
print(p, p is q)
[1, 2, 3] True
Also, L1[:] is a shallow copy: a list of objects gets a new list holding the same objects (use copy.deepcopy to copy those too).

Key takeaways


    

  1. An object lives at an address in memory; the variable you store it in (sbi) is a reference variable that holds the address. Atm() on its own creates an object you can never reach.
    2. 

  2. Since everything in Python is an object, your objects can be passed to functions and returned from them like any built-in type.
    3. 

  3. Passing an object passes the reference: same id inside and outside, so edits inside the function change the original.
    4. 

  4. Objects of your classes are mutable (id unchanged after an edit), like lists, dicts and sets; int, str and tuple are immutable.
    5. 

  5. Pass mutable data carefully; send a clone (L1[:]) if the function shouldn't touch your original.
