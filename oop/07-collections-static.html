Collections of Objects, Static Variables and Static Methods

Objects can sit in lists, tuples and dicts and be looped over like any other value. And some data shouldn't belong to any one object: a counter that numbers every customer lives on the class itself, as a static (class) variable, and the methods that only touch it need no object at all.

1 · A list of objects ▶ 2:11:41

A small topic, but handy now and then. Make three customers and put them in a list, then loop over it exactly as you would over a normal list:

class Customer:
    def __init__(self, name, age):
        self.name = name
        self.age = age

c1 = Customer('Nitish', 34)
c2 = Customer('Ankit', 45)
c3 = Customer('Neha', 32)

L = [c1, c2, c3]
for i in L:
    print(i)
<__main__.Customer object at 0x102f45fa0>
<__main__.Customer object at 0x102f45f40>

Printing an object just gives its class and memory location: the class never told Python how an object should look when printed, so all it can say is "I'm a Customer object at this address". But each i is an object, so you can use the dot on it ▶ 2:13:35:

for i in L:
    print(i.name, i.age)

2 · Calling methods in the loop ▶ 2:14:26

Not only attributes: methods work too. Give the class an intro method and call it on each object. No print around the call, since intro prints by itself.

class Customer:
    def __init__(self, name, age):
        self.name = name
        self.age = age

    def intro(self):
        print('I am', self.name, 'and I am', self.age)

L = [Customer('Nitish', 34), Customer('Ankit', 45), Customer('Neha', 32)]
for i in L:
    i.intro()
I am Nitish and I am 34
I am Ankit and I am 45
I am Neha and I am 32

3 · Dicts and tuples too ▶ 2:15:46

The same works with any collection: a dictionary or a tuple can hold objects of your class, and the loop code reads exactly the same as with normal values.

d = {'gold': L[0], 'silver': L[1]}
for tier, cust in d.items():
    print(tier, '->', cust.name)

t = (L[0], L[2])
for cust in t:
    cust.intro()
gold -> Nitish
silver -> Ankit
I am Nitish and I am 34
I am Neha and I am 32

For sets he raises a question to think about: a set accepts only immutable items, and we've just seen that our objects are mutable.

Going beyond the video. What a set really requires is that items be hashable. Objects of your own class are hashable by default: their hash comes from their identity, not their contents, so they go into a set fine, and editing an attribute doesn't disturb the set. (That changes if you define __eq__ without __hash__: then they become unhashable.) 
class Customer:
    def __init__(self, name):
        self.name = name

c1, c2 = Customer('Nitish'), Customer('Ankit')
s = {c1, c2, c1}           # objects hash by identity by default
print(len(s))
c1.name = 'Nitesh'         # mutating doesn't change the hash
print(c1 in s)

4 · The manager's request: a serial number for every customer ▶ 2:17:05


Back to the ATM. You show your manager the finished code; it works, but they want one improvement: every customer gets a serial number. The first object created is customer 1, the next is 2, then 3, and so on. Try it yourself before reading his first attempt ▶ 2:17:53:


class Atm:
    def __init__(self):
        self.pin = ''
        self.balance = 0
        self.sno = 0
        self.sno += 1

c1 = Atm()
c2 = Atm()
c3 = Atm()
print(c1.sno, c2.sno, c3.sno)


1 1 1


Doesn't work. The constructor runs every time an object is made, and each time it creates a fresh sno for that object, starting at 0. Incrementing it gets you 1, for everyone.



5 · Two kinds of variables ▶ 2:19:09


So far we've only had instance variables, whose value is different for every object: pin, balance. Pick any customer and their pin and balance are their own, as they should be. But sometimes you need a variable whose value is the same for all objects: a counter that starts at 1, gives the first customer 1, then becomes 2, gives the next customer 2, and so on. Before each new object gets its serial number, you look at the shared counter, use its value, and add 1.

If an interviewer asks "what's the difference between an instance variable and a static variable?", that's the answer: an instance variable's value is different for every object; a static variable's value is the same for every object ▶ 2:21:29. It is also called a class variable.



6 · Creating and using a static variable ▶ 2:22:11


Create it in the class but outside the constructor, and access it through the class name:


class Atm:
    counter = 1                    # static / class variable

    def __init__(self):
        self.pin = ''              # instance variables
        self.balance = 0
        self.sno = Atm.counter
        Atm.counter = Atm.counter + 1

c1 = Atm()
c2 = Atm()
c3 = Atm()
print(c1.sno, c2.sno, c3.sno)
print(Atm.counter)
print(c1.counter)


1 2 3
4
4


Every object got its own serial number, and the counter is now 4, ready for the next customer. You don't even need an object to read it: Atm.counter works directly ▶ 2:24:40. Reading it through an object (c1.counter) also gives 4, since there's just one value, but the correct way to reach a static variable is the class name.


Going beyond the video. Why insist on the class name? Reading self.counter finds the class variable, but assigning self.counter = … silently creates an instance variable on that one object, and the class's counter never moves:

class Atm:
    counter = 1

    def __init__(self):
        self.sno = self.counter
        self.counter = self.counter + 1   # creates an instance attribute!

c1 = Atm()
c2 = Atm()
print(c1.sno, c2.sno, Atm.counter, c1.counter)

The fix is the one from encapsulation: make it __counter (and rename every use), and if other programmers should still be able to read or change it, give them a getter and a setter ▶ 2:26:20. Written the usual way, though, the getter fails when called on the class:


class Atm:
    __counter = 1

    def __init__(self):
        self.sno = Atm.__counter
        Atm.__counter = Atm.__counter + 1

    def get_counter(self):      # but it never uses self...
        return Atm.__counter

Atm.get_counter()               # call it on the class, no object

8 · Static methods ▶ 2:28:15


Listen carefully here. Every method so far took self because it used the object. get_counter is called on the class (Atm.get_counter()), not on an object, so there's no object to pass in. And its code never needs self anyway; it only needs the class. So you simply don't take self.


A method that works without an object, typically one that deals with static variables, is a static method. It takes no self, and you mark it with the @staticmethod decorator to show it needs no object.


class Atm:
    __counter = 1

    def __init__(self):
        self.pin = ''
        self.balance = 0
        self.sno = Atm.__counter
        Atm.__counter = Atm.__counter + 1

    @staticmethod
    def get_counter():
        return Atm.__counter

    @staticmethod
    def set_counter(new):
        if type(new) == int:
            Atm.__counter = new
        else:
            print('Not allowed')

c1 = Atm()
c2 = Atm()
print(Atm.get_counter())
Atm.set_counter('hello')
Atm.set_counter(100)
c3 = Atm()
print(c3.sno, Atm.get_counter())
print(c1.get_counter())


3
Not allowed
100 101
101


The setter validates, just like set_pin did: only an int is allowed. And a static method can still be called through an object (last line); it just doesn't need one.


One last slip ▶ 2:30:36. While testing, he trips over the double underscores himself: a line that seemed to set the counter had really created a new variable ("sorry for this"). The trap is the same one as sbi.__balance: outside a class there's no name mangling, so Atm.__counter = … makes a new class attribute and the real counter is untouched:


class Atm:
    __counter = 1

    def __init__(self):
        self.sno = Atm.__counter
        Atm.__counter = Atm.__counter + 1

    @staticmethod
    def get_counter():
        return Atm.__counter

Atm.__counter = 'oops'     # outside the class: a NEW attribute, no harm done
c1 = Atm()
print(c1.sno, Atm.get_counter())
print(Atm.__counter)

  1. Lists, tuples and dicts can hold your objects; loop over them as usual and use i.attribute or i.method() on each.

  2. Printing an object shows only its class and address unless the class says how to display it.

  3. Instance variable: different for every object, created on self in the constructor. Static (class) variable: one value shared by all objects, created in the class outside the constructor, accessed as ClassName.var.

    6. 

  6. Atm.__counter = … written outside the class creates a new attribute; it doesn't touch the private one.
