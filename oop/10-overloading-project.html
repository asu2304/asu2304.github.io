Overloading and a Mini IRCTC Project

The last two kinds of polymorphism. Method overloading means one method name that behaves differently for different inputs; Python doesn't support it directly, but default arguments get you there. Operator overloading means giving +, * and friends your own meaning through magic methods. Then a small project: a train-information app built as a class around a web API.

2 · Method overloading ▶ 3:36:21

Method overloading means one method that can be implemented in different ways: give it different inputs and it behaves differently. His example ▶ 3:36:37: you're writing code that calculates areas. Every shape's area is computed differently, but for readability you want every one of those functions to be called area, so the name alone tells you what it does. Only the inputs differ: one number (a radius) means a circle, two numbers (length and breadth) mean a rectangle.

class Geometry:

    def area(self, radius):
        return 3.14 * radius * radius

    def area(self, l, b):
        return l * b

obj = Geometry()
print(obj.area(4))
Traceback (most recent call last):
  ...
TypeError: area() missing 1 required positional argument: 'b'

Written in Java, this exact code works perfectly: area(4) would pick the one-argument version. In Python it fails ▶ 3:38:41. The second def area with the same name simply replaces the first, so only the two-argument version exists, and calling it with one argument is an error. You can't make several methods with the same name and pick one by its inputs. Technically speaking, Python doesn't support method overloading.

The jugaad ▶ 3:39:45. With a little cleverness you can get the same behaviour: one method, with a default value on the second parameter, that branches on what it received.

class Geometry:

    def area(self, a, b=0):
        if b == 0:
            return 'Circle', 3.14 * a * a
        else:
            return 'Rectangle', a * b

obj = Geometry()
print(obj.area(4))
print(obj.area(4, 5))
('Circle', 50.24)
('Rectangle', 20)

By definition this is still method overloading: one method behaves differently depending on its input. Its limit, which he points out: if each case's logic grows large (imagine circle, rectangle, cylinder… all in one method), it becomes hard to manage, and separate functions may read better. So Python doesn't have the feature, but you can achieve the behaviour.


  




Going beyond the video: other ways to get the same effect are *args (branch on len(args)) or functools.singledispatchmethod, which picks an implementation by the type of the first argument. Default arguments, as in the video, are the most common.



3 · Operator overloading ▶ 3:42:12


Programming languages have operators (arithmetic, relational, logical), and every operator has a default behaviour. Give + two numbers and it adds them mathematically. But you've already used + for something else:


print(5 + 6)
print('hello' + 'world')
print([1, 2] + [3, 4])

Between two strings, + doesn't do mathematical addition; it joins them. Whoever built the string class told +: don't add, do this instead. That's operator overloading, and you did it yourself with the Fraction class ▶ 3:43:26 (page 4):


class Fraction:

    def __init__(self, n, d):
        self.num = n
        self.den = d

    def __str__(self):
        return '{}/{}'.format(self.num, self.den)

    def __add__(self, other):
        temp_num = self.num * other.den + other.num * self.den
        temp_den = self.den * other.den
        return Fraction(temp_num, temp_den)

x = Fraction(3, 4)
y = Fraction(5, 6)
print(x + y)
print(x.__add__(y))

x + y isn't mathematical addition here; it's fraction addition, and you wrote that logic. You overrode the behaviour of + in your class with your own custom logic, using magic methods (dunder methods): Python turns x + y into x.__add__(y), as the second print shows.

Going beyond the video: the explorer shows two rules worth knowing. (1) If the left operand's method returns NotImplemented, Python tries the right operand's reflected method: 5 * 'yo' works through str.__rmul__. (2) Without __eq__, == only checks whether both sides are the same object, so two equal-looking Fractions compare False. Fraction also breaks with plain ints ('int' object has no attribute 'den'); a sturdier version would convert them first.



4 · Project: a mini IRCTC ▶ 3:44:25


After many hours of theory, a small project: a little application like IRCTC or MakeMyTrip that does train-related operations. With a train number you could check its live status, with a PNR number its booking, plus which trains are at a station right now, seat availability on a given day, and the fare.


Where does the data come from? ▶ 3:45:04 From a website called Indian Rail API, which provides APIs. An API is like a function whose job is to fetch someone else's data and hand it to you: send the right input and it returns Indian Railways data. For example, its train schedule API: put a train number in the URL and you get back the list of stations the train passes through. To use it you create an account, log in, and get your own API key, which goes into the URL.


What comes back ▶ 3:47:08. Paste the URL in a browser with train 12222 (Howrah–Pune Duronto Express) and you get data in JSON, a very famous data format that APIs commonly return. Raw JSON is hard to read, so he pastes it into an online JSON viewer to see its tree structure. It reads exactly like a Python dictionary:

Change the train number in the URL and you get another train's route. The plan is to do all of this from Python: hit the API, receive the data, pull out the station names and display them.

6 · The code ▶ 3:50:35


The whole app is one class, IRCTC. Its constructor shows a menu and routes the choice. Only the train schedule is built; the other options just print a placeholder:


import requests

class IRCTC:

    def __init__(self):
        user_input = input("""How would you like to proceed?
1. Enter 1 to check live train status
2. Enter 2 to check PNR
3. Enter 3 to check train schedule
""")
        if user_input == "1":
            print("live train status")
        elif user_input == "2":
            print("PNR")
        else:
            self.train_schedule()

    def train_schedule(self):
        train_no = input("Enter the train number: ")
        self.fetch_data(train_no)

    def fetch_data(self, train_no):
        url = ("https://indianrailapi.com/api/v2/TrainSchedule/"
               "apikey/YOUR_API_KEY/TrainNumber/{}/").format(train_no)
        data = requests.get(url)
        data = data.json()
        for i in data['Route']:
            print(i['StationName'], i['ArrivalTime'],
                  i['DepartureTime'], i['Distance'], 'KMS')

obj = IRCTC()

7 · The bug: a hardcoded train number ▶ 3:57:37


The first run with 12222 printed a route from Ajmer to Agra Fort. That's wrong: 12222 is the Howrah–Pune Duronto. In fact, any number gave Ajmer → Agra Fort. Can you spot why before reading on?


The URL had been pasted from the browser with a train number already inside it, so train_no was never used. The fix: put {} where the number goes and call .format(train_no) on the string, which is what fetch_data above does. After that, 12222 gave Howrah → Pune and 12024 gave the Jan Shatabdi Express from Patna to Howrah.

Ideas to extend it ▶ 4:00:29. It's a console application, which can't look pretty, but you can easily turn it into a website. Add more features from the same site. He tried two more endpoints: live station (a station code such as HWH for Howrah plus a window of hours, e.g. 2–4, for the trains due there) and trains between stations (HWH → NDLS). Neither returned data at the time. Trains weren't running normally, or he may have hit the daily request limit on his free account. Try with your own key, see what data comes back, and work out how to pull the right parts from it. That's how you create applications in Python using APIs.


Going beyond the video: third-party APIs change or disappear, so the URL format and key names above (Route, StationName, …) may no longer match the live service. Three habits for real code: keep the API key out of the source (read it from an environment variable), pass timeout=10 to requests.get, and check response.status_code (and the API's own Status field) before indexing into the data. An f-string, f".../TrainNumber/{train_no}/", does the same job as .format.



Key takeaways


    

  1. Polymorphism ("many forms") has three kinds: method overriding, method overloading and operator overloading.
    2. 

  2. Python has no true method overloading: a second def with the same name replaces the first. Get the behaviour with default arguments and a branch inside one method.
    3. 

  3. Operator overloading gives an operator a custom meaning for your class through magic methods: x + y becomes x.__add__(y). str's + already does it.
    4. 

  4. The project wraps an API in a class: the constructor shows a menu, methods ask for input, requests.get(url).json() fetches the data, and you walk the dictionaries and lists to pick out what you need.
    5. 

  5. Build URLs from variables (.format or f-strings); a hardcoded value pasted from the browser makes every query return the same answer.
