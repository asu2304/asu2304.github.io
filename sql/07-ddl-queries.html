Chapter 7

DDL queries: creating and shaping databases and tables

2:18:20 → 3:00:00CREATE · DROP · TRUNCATE · ALTER7 constraintsLive SQL lab

So far we created databases and tables by clicking around in phpMyAdmin. Not every company uses phpMyAdmin, so you must know the SQL commands behind those clicks. These are DDL (Data Definition Language) commands: they define structure, not data.

Run everything on this page

Every example is runnable in the SQL lab further down: a real SQL engine in your browser. Nitish ran his in phpMyAdmin's SQL tab; that works the same way.

Databases: CREATE and DROP

CREATE DATABASE mydb;

-- safer: no error if it already exists
CREATE DATABASE IF NOT EXISTS mydb;

IF NOT EXISTS uses the EXISTS operator we met in Chapter 5. Without it, creating a database that already exists throws an error.

DROP DATABASE mydb;

-- no error if it doesn't exist
DROP DATABASE IF EXISTS mydb;
From the class Q&A

A student asked: can one command drop several databases at once? Not with a plain DROP DATABASE a, b; you write one DROP DATABASE statement per database (you can put them one after another and run them together). Some people online write their own procedures to do it, but that's beyond plain SQL.

SHOW DATABASES;   -- list all databases
USE mydb;         -- make mydb the current database for the following queries
Convention: write keywords in CAPITALS

SQL keywords are not case-sensitive: create database works too. But it's conventional to write all keywords (CREATE, TABLE, NOT NULL…) in capitals and your own names in lowercase, for readability. It isn't mandatory; it's what everyone does.

Tables: CREATE, DROP, TRUNCATE

Two ways to create a table: the phpMyAdmin form (name, number of columns, then fill in each column's details and click Go), or one SQL command:

CREATE TABLE users (
    user_id  INTEGER,
    name     VARCHAR(255),
    email    VARCHAR(255),
    password VARCHAR(255)
);

-- or, without an error if it already exists:
CREATE TABLE IF NOT EXISTS users ( … );

Pattern: column_name DATA_TYPE, with a comma after every column definition except the last. Forgetting a comma is the most common error at this stage.

DROP TABLE users;              -- delete the table: structure + data
DROP TABLE IF EXISTS users;

TRUNCATE TABLE users;          -- keep the table, remove ALL rows

In phpMyAdmin both live under the table's Operations tab: "Delete the table (DROP)" and "Empty the table (TRUNCATE)". After a truncate, Browse shows zero rows but the columns are still there.

Constraints: rules that protect integrity

In Chapter 3 we said a database maintains integrity through constraints. Now we write them. Constraints are usually added when you create the table (you can also add or remove them later with ALTER). The course covers seven:

NOT NULL

A value is required.

UNIQUE

No two rows may share the value.

PRIMARY KEY

UNIQUE + NOT NULL, one per table.

AUTO_INCREMENT

The DB fills in 1, 2, 3, … for you.

CHECK

Value must satisfy a condition.

DEFAULT

Value used when none is given.

FOREIGN KEY

Value must exist in another table.

1 · NOT NULL

CREATE TABLE users (
    id    INTEGER NOT NULL,
    name  VARCHAR(255) NOT NULL,
    email VARCHAR(255) NOT NULL,
    password VARCHAR(255) NOT NULL
);

Now any INSERT that leaves one of these empty fails. Use it for anything that must always be there (name, email…).

2 · UNIQUE

The value must not repeat across rows; perfect for emails. Two ways to write it:

CREATE TABLE users (
    id    INTEGER NOT NULL,
    name  VARCHAR(255) NOT NULL,
    email VARCHAR(255) NOT NULL UNIQUE,
    password VARCHAR(255) NOT NULL
);
CREATE TABLE users (
    id    INTEGER NOT NULL,
    name  VARCHAR(255) NOT NULL,
    email VARCHAR(255) NOT NULL,
    password VARCHAR(255) NOT NULL,

    CONSTRAINT users_email_unique UNIQUE (email)
);
-- the PAIR (name, email) must be unique;
-- the same name with a different email is fine
CONSTRAINT users_name_email_unique UNIQUE (name, email)
Why give a constraint a name?

Writing CONSTRAINT <name> … takes a little longer, but it lets you refer to the constraint later, e.g. to drop it with ALTER TABLE … DROP CONSTRAINT users_email_unique. A common naming pattern is table_column_type. It also lets you apply one rule to several columns together.

3 · PRIMARY KEY

The column(s) that uniquely identify each row: implicitly unique and not null. Again two ways:

CREATE TABLE students (
    id   INTEGER PRIMARY KEY,
    name VARCHAR(255) NOT NULL
);
CREATE TABLE students (
    id   INTEGER NOT NULL,
    name VARCHAR(255) NOT NULL,

    CONSTRAINT students_pk PRIMARY KEY (id)
    -- composite: PRIMARY KEY (id, name)
);

With the table-level form you can make a composite primary key by listing several columns: then the combination must be unique.

4 · AUTO_INCREMENT

CREATE TABLE passengers (
    id   INTEGER PRIMARY KEY AUTO_INCREMENT,
    name VARCHAR(255) NOT NULL
);

INSERT INTO passengers (name) VALUES ('Nitish');   -- id = 1
INSERT INTO passengers (name) VALUES ('Ankit');    -- id = 2

You don't provide the id; the database looks at the last one and adds 1. This is how you make a surrogate key.

5 · CHECK

Only accept values that satisfy a condition. Example: a school's students must be older than 6 and younger than 25.

CREATE TABLE students (
    id   INTEGER PRIMARY KEY,
    name VARCHAR(255) NOT NULL,
    age  INTEGER,

    CONSTRAINT students_age_check CHECK (age > 6 AND age < 25)
);

INSERT INTO students VALUES (1, 'Rahul', 20);  -- ✓
INSERT INTO students VALUES (2, 'Amit', 40);   -- ✗ Check constraint violated
Note

MySQL only enforces CHECK from version 8.0.16; older versions accepted the syntax but silently ignored it. XAMPP ships MariaDB, which enforces it.

6 · DEFAULT

If an insert doesn't provide a value for the column, use this one instead of NULL. A classic use is recording when a row was created:

CREATE TABLE passengers (
    id     INTEGER PRIMARY KEY AUTO_INCREMENT,
    name   VARCHAR(255) NOT NULL,
    joined DATETIME DEFAULT CURRENT_TIMESTAMP
);

INSERT INTO passengers (name) VALUES ('Nitish');
-- joined is filled with the current date and time automatically

Logical uses: a user's registration time, a default status like 'pending', a default country…

7 · FOREIGN KEY

Links a column to the primary key of another table, enforcing referential integrity: you can't insert an order for a user who doesn't exist, and you can't simply delete a user who still has orders.

CREATE TABLE customers (
    cid   INTEGER PRIMARY KEY AUTO_INCREMENT,
    name  VARCHAR(255) NOT NULL,
    email VARCHAR(255) NOT NULL UNIQUE
);

CREATE TABLE orders (
    order_id   INTEGER PRIMARY KEY AUTO_INCREMENT,
    cid        INTEGER NOT NULL,
    order_date DATETIME DEFAULT CURRENT_TIMESTAMP,

    CONSTRAINT orders_fk FOREIGN KEY (cid) REFERENCES customers(cid)
);

Notice orders has its own primary key (order_id), while cid is just an integer that must match a customers.cid. In class, trying to drop the parent table while orders still referenced it failed with a foreign-key error, which is exactly the protection we want.

Referential actions: what happens on delete / update

You decide what the database does to child rows when the parent row is deleted or its key is updated:

ActionEffect on the child rows (orders)
RESTRICT / NO ACTIONDefault. Refuse to delete/update the parent while children exist.
CASCADEDelete/update the children too (delete a customer → their orders go).
SET NULLKeep the children but set their FK to NULL (column must allow NULL).
SET DEFAULTSet the FK to its default value (not supported by MySQL's InnoDB engine).
CONSTRAINT orders_fk FOREIGN KEY (cid) REFERENCES customers(cid)
    ON DELETE CASCADE
    ON UPDATE CASCADE

Remember the branch example from Chapter 3: renaming CSE → CS updates every student automatically with ON UPDATE CASCADE.

ALTER TABLE: changing an existing table

Tables change over time. ALTER TABLE lets you add, delete and modify columns, and add or remove constraints, without recreating the table.

ALTER TABLE students ADD COLUMN college VARCHAR(255) NOT NULL;

-- choose the position (MySQL)
ALTER TABLE students ADD COLUMN college VARCHAR(255) NOT NULL AFTER name;

-- several at once
ALTER TABLE students
    ADD COLUMN city VARCHAR(255) AFTER college,
    ADD COLUMN cgpa DECIMAL(3,2) AFTER city;
ALTER TABLE students DROP COLUMN cgpa;

-- several at once
ALTER TABLE students DROP COLUMN city, DROP COLUMN college;
-- change a column's data type / definition (MySQL)
ALTER TABLE students MODIFY COLUMN name INTEGER;

-- rename a column
ALTER TABLE students RENAME COLUMN name TO full_name;

MODIFY replaces the whole definition, so restate anything you want to keep (e.g. NOT NULL).

ALTER TABLE passengers
    ADD CONSTRAINT passengers_email_unique UNIQUE (email);

This fails if the existing data already breaks the rule. In class the table already had two rows with the same email, so MySQL refused with a duplicate entry error. Fix the data first, then add the constraint.

ALTER TABLE passengers DROP CONSTRAINT passengers_email_unique;
-- older MySQL: ALTER TABLE passengers DROP INDEX passengers_email_unique;

After dropping it, inserting a duplicate email works again. This is where naming your constraints pays off.

You can't edit a constraint in place

To change a constraint (say, a different CHECK condition), drop it and add a new one.

Delete a databaseDROP DATABASE IF EXISTS db;
Create a tableCREATE TABLE t (col TYPE constraints, …);
Delete a tableDROP TABLE IF EXISTS t;

Check yourself

You want to remove every row from users but keep the table and its columns. Which DDL command?

TRUNCATE empties the table; DROP removes it entirely.

What does IF NOT EXISTS in CREATE TABLE IF NOT EXISTS users (…) do?

It avoids the "table already exists" error and leaves the existing table untouched.

Which constraint makes the database fill in the current time when you don't supply one?

DEFAULT supplies a value when the insert omits the column.

ALTER TABLE passengers ADD CONSTRAINT p_email_unique UNIQUE (email); fails with "Duplicate entry". Why?

The data must already satisfy a constraint before you can add it. Clean the duplicates first.

A customers row is deleted and all of that customer's orders disappear automatically. Which referential action is on the foreign key?

CASCADE propagates the delete to child rows. RESTRICT would have refused the delete; SET NULL would keep the orders with cid = NULL.

How do you change the condition of an existing named CHECK constraint?

Constraints can't be edited in place: drop and re-add, which is easy when you named it.

Conceptual questions

The questions above test facts. These check whether you understand why; several go one step beyond the video.

You need to remove all rows from a 50-million-row log table quickly and keep its structure. Which is the better choice and why?

TRUNCATE is fast but can't be filtered with WHERE, and in MySQL it can't be rolled back.

Is a column with a UNIQUE constraint allowed to hold several NULLs (in MySQL)?

That's a key difference from a PRIMARY KEY, which forbids NULL entirely.

Which is the closest description of PRIMARY KEY?

A table can have many UNIQUE columns but only one primary key.

orders.cid references customers with ON DELETE SET NULL, but cid is declared NOT NULL. What happens?

Referential actions must be compatible with the column's constraints.

Why should you name constraints (e.g. CONSTRAINT users_email_unique UNIQUE (email))?

Auto-generated names are hard to guess when you need to ALTER them.
