Chapter 10

CASE: if / else inside a query

4:42:00 → 4:48:00CASE WHEN … THEN … ELSE … ENDShort but frequently used

Every programming language has if/else. In SQL it's the CASE statement: it lets a query produce different output values depending on conditions, which is perfect for turning numbers into labels.

The class example: box-office verdicts

Compute each Bollywood movie's profit (worldwide − budget, in ₹ crore) and label it:

SELECT title,
       worldwide - budget AS profit,
       CASE
           WHEN worldwide - budget > 100 THEN 'Superhit'
           WHEN worldwide - budget > 25  AND worldwide - budget <= 100 THEN 'Hit'
           WHEN worldwide - budget >= 0  AND worldwide - budget <= 25  THEN 'Average'
           ELSE 'Flop'
       END AS verdict
FROM movies;

Anatomy of CASE

  • Starts with CASE, ends with END; give the result a name with AS.
  • Each WHEN condition THEN value is an "if / else-if". They are checked top to bottom, and the first true one wins.
  • ELSE catches everything else. Without it, unmatched rows get NULL.
  • The whole CASE is just an expression, so it sits in the SELECT list like any column.
Shorter, thanks to top-to-bottom order

Because earlier WHENs have already caught the bigger values, the lower bounds are redundant:

SELECT title,
       CASE
           WHEN worldwide - budget > 100 THEN 'Superhit'
           WHEN worldwide - budget > 25  THEN 'Hit'
           WHEN worldwide - budget >= 0  THEN 'Average'
           ELSE 'Flop'
       END AS verdict
FROM movies;

Going further (my additions)

How many movies fall in each verdict? Group by the CASE expression:

SELECT CASE
           WHEN worldwide - budget > 100 THEN 'Superhit'
           WHEN worldwide - budget > 25  THEN 'Hit'
           WHEN worldwide - budget >= 0  THEN 'Average'
           ELSE 'Flop'
       END AS verdict,
       COUNT(*) AS movies
FROM movies
GROUP BY verdict
ORDER BY movies DESC;

Count different things in one pass by putting CASE inside an aggregate:

SELECT pclass,
       SUM(CASE WHEN sex = 'female' THEN 1 ELSE 0 END) AS women,
       SUM(CASE WHEN sex = 'male'   THEN 1 ELSE 0 END) AS men
FROM train
GROUP BY pclass;

When you're only matching exact values of one column, there's a shorter form:

SELECT name,
       CASE embarked
           WHEN 'S' THEN 'Southampton'
           WHEN 'C' THEN 'Cherbourg'
           WHEN 'Q' THEN 'Queenstown'
           ELSE 'Unknown'
       END AS port
FROM train;
-- Drama first, then Action, then everything else
SELECT title, genre FROM movies
ORDER BY CASE genre WHEN 'Drama' THEN 1 WHEN 'Action' THEN 2 ELSE 3 END, title;

Check yourself

A movie has profit 150. With the WHENs ordered "> 25 → Hit" first and "> 100 → Superhit" second, what label does it get?

Order matters: put the most specific (strictest) condition first.

What does a CASE return for a row that matches no WHEN and has no ELSE?

Always add an ELSE if you don't want NULLs.

Which keyword closes a CASE expression?

CASE … END, optionally followed by AS name.

Conceptual questions

The questions above test facts. These check whether you understand why; several go one step beyond the video.

Why does SUM(CASE WHEN sex = 'female' THEN 1 ELSE 0 END) count women?

This "conditional aggregation" pattern builds pivot-style reports in one query.

Could you use WHERE instead of CASE to produce the four verdict labels in one result?

WHERE filters; CASE computes. You'd need four separate queries with WHERE.

In the verdict query, what label does a NULL profit (unknown budget) get?

That's misleading. Add WHEN profit IS NULL THEN 'Unknown' first.
