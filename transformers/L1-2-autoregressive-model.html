The Autoregressive Probability Model

A categorical distribution over whole sequences would need $|V|^T$ probabilities. The chain rule turns it into a product of next-token distributions, each only $|V|$-way, and a single network maps “everything so far” to the logits of the next token: embed the tokens, run the transformer, take a softmax at every position.

1 · Too many sequences to list ▶ 10:51

We want a probabilistic model of sequences $x_1,\dots,x_T$ with $x_i\in V$. Count the support: each position has $|V|$ choices, and there are $T$ positions, so

$$\#\{\text{possible sequences}\} = |V|^T .$$

Treating this as one big categorical distribution, with one probability per sequence, is "way too many parameters to describe it".

2 · The chain rule: one next-token distribution at a time ▶ 11:52

Instead, decompose the joint distribution with the chain rule of probability:

$$p(x_1,\dots,x_T)=p(x_1)\,p(x_2\mid x_1)\,p(x_3\mid x_1,x_2)\cdots p(x_T\mid x_1,\dots,x_{T-1}).$$

The benefit: each factor is a distribution over a single token, so it has only $|V|$ choices. It can be produced by some logits followed by a softmax over $|V|$ entries.

Each conditional is parametrised by a neural network, the transformer: its input is what comes after the conditioning bar (e.g. $x_1,x_2$), its output is the distribution of the next token ($x_3$). We are going to model $p_\theta(x_t\mid x_1,\dots,x_{t-1})$.

3 · Treat the network as a black box: what goes in, what comes out ▶ 13:54

Before opening the transformer, the lecture fixes its "boundary". It has multiple layers; the typical parametrisation runs as follows.

Embeddings ▶ 14:10

The $x_t$ are discrete IDs, so first turn each into numbers: an embedding $e(x_t)\in\mathbb R^d$. The embeddings are trained: they start as unknown parameters and training finds the right values. Every token in the vocabulary has its own embedding, so they form an embedding matrix

$$E\in\mathbb R^{|V|\times d}\quad(\text{row } i = \text{embedding of token } i).$$

To get the embedding of the 5th token, read off the 5th row; equivalently, multiply the one-hot indicator row vector of token 5 by $E$. Same thing. The embedding depends only on the token itself, nothing else in the sequence.

A convention: row vectors ▶ 15:22

For the LLM lectures every vector is a row vector and matrices multiply on the right ($hW$, not $Wh$). Mathematics and many papers use column vectors, and the lecturer admits it looks a bit odd to him, but rows match the code, where a vector is a row of an array.

The beginning-of-sentence token ▶ 16:35

Often a fixed beginning-of-sentence token $x_0$ (always the same) is prepended. Not always necessary, but we'll use it. It is one of the special tokens: vocabularies are usually bigger than needed, with maybe a few thousand IDs reserved for special purposes.

Logits and softmax at every position ▶ 17:20

The embeddings $e(x_0),e(x_1),\dots$ go through the transformer (attention, matrix multiplications, lots of operations; defined later). It outputs a vector of logits at each position, $u_t\in\mathbb R^{|V|}$, describing the conditional distribution before the softmax:

$$u_t = f_\theta(x_0,\dots,x_{t-1}),\qquad p_\theta(x_t\mid x_1,\dots,x_{t-1})=\operatorname{softmax}(u_t).$$
  • First token (nothing to condition on): $p_\theta(x_1)=\operatorname{softmax}(f_\theta(x_0))$, the output at the BOS position.
  • Second: $p_\theta(x_2\mid x_1)=\operatorname{softmax}(u_2)$ with $u_2=f_\theta(x_0,x_1)$. And so on.

After the softmax the vector lies in the probability simplex: entries non-negative, summing to 1.

4 · Questions from the class ▶ 20:44

Is $u_t$ different from $f_\theta(x_0,\dots,x_{t-1})$? No, they are the same vector. $u_t$ is a name for it; $f_\theta(\cdot)$ makes explicit what it depends on.

What does an entry of the softmax mean? The $i$-th entry is the probability that the next token is token $i$:

$$p_\theta(x_t=i\mid x_1,\dots,x_{t-1})=\big[\operatorname{softmax}(f_\theta(x_0,\dots,x_{t-1}))\big]_i ,\quad i=1,\dots,|V|.$$

Is this like masked attention, conditioning only on earlier tokens? Yes: so far this is a causal model, and that's why the notation insists $u_t$ is a function of $x_0,\dots,x_{t-1}$ only, never of later inputs. The transformer's inner workings will have to guarantee it (part 5).

Why write it as a function of the $x$'s rather than the embeddings? The embeddings are inner workings; token ↔ embedding is one-to-one, so there is no real difference.

The conditional probabilities are invented for illustration; the point is that the joint is the product of the per-position factors.

5 · This is the whole probabilistic model ▶ 25:57

That completes the description. Given any data sequence, you can compute its likelihood under $p_\theta$, which is what training needs: compute the likelihood, then maximise it as a function of $\theta$ (next part). Generation also falls out of the same model.

Key takeaways

  1. A direct categorical over sequences needs $|V|^T$ probabilities; impossible.
  2. The chain rule factors $p(x_{1:T})$ into $T$ next-token conditionals, each a softmax over just $|V|$ entries.
  3. Tokens → trained embeddings (rows of $E\in\mathbb R^{|V|\times d}$, row-vector convention) with a BOS token $x_0$ in front.
  4. $u_t=f_\theta(x_0,\dots,x_{t-1})\in\mathbb R^{|V|}$ and $p_\theta(x_t\mid x_{<t})=\operatorname{softmax}(u_t)$; entry $i$ is the probability the next token is $i$.
  5. $u_t$ must not depend on $x_t,x_{t+1},\dots$: the model is causal, and the transformer must enforce it.
