Inside the Transformer: Single-Head Attention

A transformer alternates two kinds of layer: an MLP that processes each position on its own, and attention, the only place where positions talk to each other. In single-head attention each position forms a query, compares it with every position's key by an inner product, turns the scores into probabilities with a softmax, and outputs the probability-weighted average of the values.

1 · The big picture: attention and MLP, alternating ▶ 39:27

Start from the embeddings $e(x_1),\dots,e(x_T)$. The transformer has multiple layers:

embeddings → attention → MLP → attention → MLP → … → MLP → $u_1,\dots,u_T$

  • Attention always takes in a sequence of vectors and outputs a sequence of vectors, one per position.
  • Each output vector then goes through an MLP (multi-layer perceptron: a two- or three-layer network, with some special gating or activation function).
  • Alternate enough times; the last layer outputs the logit vectors $u_1,\dots,u_T$.

2 · The MLP is per-position; only attention mixes positions ▶ 41:12

The lecture focuses on attention, the new ingredient. One more fact about the MLP: it shares its parameters across positions and is applied to each position independently. There are no dependencies between positions inside an MLP, so it is very parallelisable.

The only way information from different positions (time steps) is fused is attention: it looks at all the vectors, processes them, and outputs a new sequence.

Is the whole thing trained as one system? ▶ 41:54 Yes: define the architecture, then train it end to end as one gigantic network with auto-differentiation. Autodiff only needs the forward pass to be a composition of basic operations; attention and the MLP are many small matrix multiplications, so the backward pass comes for free.

3 · Single-head attention: queries, keys, values ▶ 43:01

Type signature: input $h^{\text{in}}_1,\dots,h^{\text{in}}_T$, output $h^{\text{out}}_1,\dots,h^{\text{out}}_T$. Everything is a row vector, multiplied on the right. With $h^{\text{in}}_t\in\mathbb R^{1\times d}$ and three trained weight matrices in $\mathbb R^{d\times d_h}$ ($d_h$ is a dimension you choose):

$$q_t = h^{\text{in}}_t W_Q,\qquad k_t = h^{\text{in}}_t W_K,\qquad v_t = h^{\text{in}}_t W_V,\qquad q_t,k_t,v_t\in\mathbb R^{1\times d_h}.$$

Do this at every position to get queries $q_1,\dots,q_T$, keys $k_1,\dots,k_T$ and values $v_1,\dots,v_T$ ("values" as in vectors, not value functions).

4 · The intuition: whom should I pay attention to? ▶ 46:12

The intuition isn't obvious ("eventually, it just works; nobody really knows exactly how"), but roughly: positions must interact, or each time step is processed independently. Interaction is about retrieving, or paying attention to, each other. When processing one vector, you should attend to the other vectors that carry relevant information, and compute your output mostly from those. Queries and keys decide which positions to attend to; values carry what you retrieve.

5 · Scores, softmax, weighted sum ▶ 47:45

  1. Scores. For position $t$, take the inner product of its query with every key: $q_tk_1^\top,\ q_tk_2^\top,\ \dots,\ q_tk_T^\top$. Since $q_t$ is a row and $k_i^\top$ a column, each is a scalar, so you get $T$ real numbers. There is often a scaling factor $c$ dividing them to keep things well-behaved; the lecture says not to worry about it for now.
  2. Softmax over positions. $$(P_{t1},\dots,P_{tT}) = \operatorname{softmax}\!\Big(\tfrac{q_tk_1^\top}{c},\dots,\tfrac{q_tk_T^\top}{c}\Big),\qquad P_{ti}\ge0,\ \ \sum_{i=1}^T P_{ti}=1 .$$ A probability vector over the $T$ positions. A large $P_{ti}$ means $q_t$ and $k_i$ have a high inner product: position $t$ should pay more attention to position $i$.
  3. Output ▶ 51:29: use those probabilities to weight the values, $$h^{\text{out}}_t = P_{t1}v_1 + P_{t2}v_2 + \cdots + P_{tT}v_T .$$ If $P_{t2}$ is very big, the output at time $t$ uses $v_2$ a lot.
Going beyond the lecture. The usual choice is $c=\sqrt{d_h}$: if query and key entries are roughly independent with unit variance, $q_tk_i^\top$ has variance $d_h$, so dividing by $\sqrt{d_h}$ keeps the scores around unit scale and the softmax from saturating. It's the same effect as temperature on page 3: a larger $c$ means a softer attention pattern.

Try it with $d_h=2$ so the vectors can be drawn. Five positions have fixed keys (dots); drag or tap to move the query $q_t$. To make the weighted sum visible, each value $v_i$ is a 3-vector read as a colour, and the output $h^{\text{out}}_t$ is the mixed colour.

Point the query at one key and that position takes most of the weight; point it between two keys and the output is a blend; shrink $c$ and the choice becomes nearly one-hot.

6 · Where do the weights come from? ▶ 52:28

$W_Q,W_K,W_V$ are trained, so how positions attend to each other is learned too. The architecture is only a template. If all the weights were 0 it would still be a valid network, just one with a bad loss; training chooses $W$ so that the mechanism does the right thing.

7 · Why not just MLPs? ▶ 53:27

AlternativeProblem
Remove attention, keep per-position MLPsNo interaction between positions at all: separate networks for each token. Like reading individual words with no sentence; no chance of understanding dependencies or meaning.
One gigantic MLP on all $T$ vectors concatenated(1) Far too many parameters: $T$ can be a million, and a million-by-million weight matrix is far too big. (2) The parameter count changes with $T$: train at length 1,000, test at 1,001, and the network no longer fits.
Just average the vectorsNo parameters: prescribes too much structure, no flexibility.
Attention$W_Q,W_K,W_V$ act on one position's vector, so the parameter count does not depend on $T$; the learned scores still let any position use any other.

A student put it well: with enough compute and data (so you don't overfit) some gigantic MLP could solve the problem, but that's too expensive. You prescribe structure to cut the complexity while leaving enough flexibility for the model to figure the rest out. Attention strikes that balance.

Parameter counts for one layer (weights only). The concatenated MLP is taken as a single $(Td)\times(Td)$ matrix, the most generous version.

single-head attention, $3\,d\,d_h$ ($d_h=d$)
concatenated MLP, $(Td)^2$

8 · A note from history: convolutions ▶ 57:09

Sequences have been handled in other ways, e.g. a convolutional network: an MLP with a limited receptive field, so each step sees only a window. Some papers say it isn't a terrible idea and works to some degree, just not as well as attention. There are also attention variants that do similar things with better efficiency; they come later. And single-head attention is not the whole story yet.

Key takeaways

  1. A transformer alternates attention and position-wise MLPs; the MLP shares weights across positions and never mixes them.
  2. $q_t=h_tW_Q$, $k_t=h_tW_K$, $v_t=h_tW_V$ (row vectors, $W\in\mathbb R^{d\times d_h}$, all trained).
  3. $P_{t\cdot}=\operatorname{softmax}_i(q_tk_i^\top/c)$; high inner product ⇒ more attention.
  4. $h^{\text{out}}_t=\sum_iP_{ti}v_i$, a convex combination of the values.
  5. Attention's parameter count is independent of $T$, unlike a concatenated MLP: structure balanced against flexibility.
