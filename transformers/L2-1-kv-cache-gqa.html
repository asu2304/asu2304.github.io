The KV Cache and Grouped-Query Attention

When a transformer generates text, it must keep every past key and value of every head in GPU memory. That KV cache limits how many sequences fit in a batch, and a small batch leaves the GPU's compute idle. Grouped-query attention cuts the cache by letting several query heads share one set of keys and values.

2 · Recap: queries, keys and values ▶ 1:23

For a single head, every time step $t=1,\dots,T$ has a query vector $q_t$, a key vector $k_t$ and a value vector $v_t$. Attention takes inner products of queries with keys, applies a softmax, and uses the result to average the values.

The model is autoregressive: a position never attends to anything after it. So $q_1$ attends to $k_1$; $q_2$ attends to $k_1,k_2$; and $q_T$ attends to everything up to time $T$. Drawn as a $T\times T$ matrix of query–key pairs, only the triangle on and below the diagonal is used: roughly half the entries.

Stack the vectors as rows: $Q$ has rows $q_1,\dots,q_T$, and likewise $K$ and $V$. Then one head computes

$$\operatorname{out}=\operatorname{softmax}\!\Big(\frac{QK^\top}{c}+M\Big)\,V ,$$

where entry $(t,s)$ of $QK^\top$ is $q_t k_s^\top$, the mask $M$ is $0$ where $s\le t$ and $-\infty$ where $s>t$ (so those weights become $e^{-\infty}=0$), the softmax is taken row by row, and $c$ is a normalising constant (section 6).

Multiple heads are many copies of this: the same architecture with different weights. Head $j$ has its own $q_{1,j},\dots,q_{T,j}$, $k_{1,j},\dots,k_{T,j}$ and $v_{1,j},\dots,v_{T,j}$. (Full derivation: attention and masking, multi-head attention and cost in Lecture 1.)

Going beyond the lecture. The same equation, with a picture of the mask, is in my notes on Prof. Khapra's lectures: scaled dot-product attention, multi-head attention and the masked decoder.

3 · What attention costs: $T^2$ compute and a KV cache ▶ 4:45

Compute scales at least like $T^2$: every query meets every earlier key.

Memory scales like $T$, and the interesting point is what must be stored during generation:

  1. To produce the token after step $t$, you need the newest query $q_t$ only. Older queries $q_1,\dots,q_{t-1}$ have already been used against their keys, so they can be dropped.
  2. But $q_t$ must meet all keys $k_1,\dots,k_t$, and its weights then average all values $v_1,\dots,v_t$. So every past key and value must be kept.
  3. That is linear in $T$, and it is needed for every head (and every layer). This stored set is the KV cache.

4 · Why a big KV cache hurts ▶ 5:50

The details are a systems topic, but the chain of cause and effect is simple:

  1. The KV cache takes a lot of GPU memory. Sometimes the cache of one sequence uses most of it; maybe you can hold 10 or 100 sequences, but there is a limit.
  2. So at inference time you cannot have a large batch: there is no room for every sequence's cache.
  3. With a small batch there is too little parallelism across examples to keep the GPU's arithmetic units busy (low arithmetic intensity, covered earlier in the course).
  4. The GPU becomes memory-bound: it waits for data while compute sits idle, which shows up as low throughput or low MFU (model FLOPs utilisation).
Hence the goal: store less KV cache. Grouped-query attention is one way, which the lecturer associates with models such as Qwen and DeepSeek.

5 · Grouped-query attention ▶ 7:31

We cannot save along the time dimension; every past position is genuinely needed. So save along the head dimension: keep all $n_h$ sets of queries, but have far fewer sets of keys and values.

  • Queries: $n_h$ sequences, $q_{1,j},\dots,q_{T,j}$ for heads $j=1,\dots,n_h$.
  • Keys and values: only $n_g$ sequences (groups), $k_{1,s},\dots,k_{T,s}$ and $v_{1,s},\dots,v_{T,s}$ for $s=1,\dots,n_g$, with $n_g<n_h$.
  • Usually $n_g$ divides $n_h$, so the sharing is even: $n_h=\tau\,n_g$, and each group of $\tau$ query heads uses the same keys in its softmax and the same values afterwards.

From the Q&A: with $n_g=2$ groups and $n_h=100$ heads, $\tau=50$, so every 50 heads share one set of keys and values.

Each head still produces its own output, so there are as many outputs as before. The only change is that some heads look at the same keys.

6 · The same thing in equations ▶ 12:00

The lecturer says the picture is the easiest way to see it, but writes the maths for completeness.

  1. Query matrices, one per head: $Q_j$ has rows $q_{1,j},\dots,q_{T,j}$ (time down the rows), for $j=1,\dots,n_h$.
  2. Key and value matrices, one per group: $K_s$ with rows $k_{1,s},\dots,k_{T,s}$ and $V_s$ with rows $v_{1,s},\dots,v_{T,s}$, for $s=1,\dots,n_g$.
  3. Map each head to its group: $$g(j)=\Big\lfloor \frac{j-1}{\tau}\Big\rfloor+1\ \in\{1,\dots,n_g\}.$$ With $\tau=2$: heads 1, 2 → group 1; heads 3, 4 → group 2; and so on.
  4. Head $j$ attends to its group's keys and values: $$\operatorname{out}_j=\operatorname{softmax}\!\Big(\frac{Q_j K_{g(j)}^\top}{c}+M\Big)\,V_{g(j)} .$$

Going beyond the lecture: the arithmetic in the demo. Per token, each layer stores one key and one value vector of size $d_h$ per KV set, so the cache is $2\cdot L\cdot n_g\cdot d_h\cdot(\text{bytes per number})$ per token. The demo uses $d_h=128$ and 2-byte (16-bit) numbers. With $n_h=n_g=32$, 32 layers and $T=8192$, that is 0.5 MiB per token and 4 GiB per sequence; cutting to $n_g=8$ fits four times as many sequences. Real systems also store weights and activations, so treat the batch count as an upper bound.

7 · Why divide by $c=\sqrt{d_h}$? ▶ 15:18

Whether in GQA or standard multi-head attention, $Q_jK^\top$ is a $(T\times d_h)$ times $(d_h\times T)$ product: every entry is the inner product of two vectors of dimension $d_h$. The constant $c$ keeps the input to the softmax on a sensible scale.

  1. Take two vectors $a,b$ of dimension $d_h$ that are "somewhat random", with each entry $a_i,b_i$ on the order of $\pm1$.
  2. Then $a\cdot b=\sum_{i=1}^{d_h}a_ib_i$ is typically on the order of $\sqrt{d_h}$: the terms have random signs and partly cancel.
  3. Dividing by $c=\sqrt{d_h}$ brings it back to order 1, so the scale does not depend on $d_h$. You can change the head dimension without retuning the rest of the architecture.

The lecturer stresses this is a heuristic. Other theories give other predictions: if $a$ and $b$ are already aligned in some direction rather than random, a different constant would be right. You can only justify the choice loosely, try it, and keep it if it works, and empirically $\sqrt{d_h}$ is one working choice.

Going beyond the lecture. For independent random signs, $\mathbb E[a_ib_i]=0$ and $\operatorname{Var}(a_ib_i)=1$, so $\operatorname{Var}(a\cdot b)=d_h$ and the standard deviation is exactly $\sqrt{d_h}$. Without the scaling, a large $d_h$ makes the softmax almost one-hot, and its gradients nearly vanish. Tick "aligned" to see the lecturer's caveat: when $a$ and $b$ point the same way, $a\cdot b$ grows like $d_h$, and dividing by $\sqrt{d_h}$ no longer tames it.

Key takeaways

  1. One head computes $\operatorname{softmax}(QK^\top/c+M)V$, with a causal mask so $q_t$ only sees $k_1,\dots,k_t$; multi-head attention repeats this with different weights.
  2. Compute grows like $T^2$; during generation only the newest query is needed, but every past key and value of every head must be kept: the KV cache.
  3. A large KV cache limits the batch size, so the GPU is memory-bound and its compute is under-used.
  4. Grouped-query attention keeps $n_h$ query heads but only $n_g=n_h/\tau$ key/value sets; head $j$ uses set $g(j)=\lfloor (j-1)/\tau\rfloor+1$, shrinking the cache by a factor $\tau$.
  5. Dividing scores by $c=\sqrt{d_h}$ is a heuristic that keeps the softmax input at order 1 for random-like vectors, whatever $d_h$ is.
