Multi-Query Attention, Sliding Windows and QK-Norm

Grouped-query attention has one knob, how many heads share a key/value set; turned all the way it becomes multi-query attention. Sliding-window attention attacks the other cost, the $T^2$ compute, by letting each query see only the last $w$ keys, which still reaches $l\cdot w$ tokens back through $l$ layers. Normalising queries and keys keeps the attention scores on scale.

1 · Why share keys and values, not queries? ▶ 18:12

A student asks why grouped-query attention reduces the number of keys rather than the number of queries. The reason is the generation-time memory picture from part 1:

  • At time $T$ you only need the query at time $T$. The queries of earlier steps have already been compared with their keys and can be thrown away. (During prefilling or training all queries are needed, but the concern here is generation.)
  • Keys and values must be kept for the whole sequence.

So query memory is small and KV memory is large, and the incentive is to cut keys and values. You could cut queries too, but cutting everything uniformly is just using fewer heads.

2 · Choosing $\tau$: from GQA to multi-query attention ▶ 20:54

There are three numbers, $n_h$, $n_g$ and $\tau$, tied by $n_h=\tau\,n_g$. Beyond respecting that equation, you pick what works empirically. The trade-off at the extreme:

  • With $\tau=n_h$ you get $n_g=1$: one set of keys and values for all heads. That is the smallest possible memory cost.
  • But you may then store too little. The cache exists to remember what happened in the history, and how much needs remembering is something to tune.

The case $n_g=1$ is called multi-query attention. It came first: one paper made that choice and was the first along this line. Later work judged it too aggressive and moved to larger $n_g$. (Asked for typical values, the lecturer isn't sure off-hand and says you'd need to check the code.)

3 · Does it matter which heads share? ▶ 22:47

Another student asks whether the order of the grouping, which heads go to which key set, means anything. It doesn't: everything is learned. Keys are not designed by hand, so if you permute the wiring, training simply adapts to it. Any two wirings with the same shape are equivalent.

Could you use richer structures, say a tree, or a query that attends to two key sets? The lecturer doesn't think people have tried. And the structure can't be very dynamic anyway: to run fast it is essentially hard-coded and compiled for the GPU, so you must know exactly what is computed. In practice people do literally the simple grouping above, with attention to locality: for example, put a key set and its queries on one GPU card and the next key set with its queries on another, to cut communication.

A last question returns to the meaning of queries and keys: if they measure how related the current word is to another word, does each depend only on its own word? Roughly, the intuition is right, but word level is too fine: each query and key also depends on nearby words (through the layers below).

4 · Sliding-window attention ▶ 26:11

GQA is about memory. Compute is also a problem: pairwise inner products between $T$ queries and $T$ keys cost $T^2$. If $T$ is a million, a million squared is a really big number, so we want to escape the quadratic dependence.

How frontier labs do it isn't public. One approach used in the open-source community is simply not computing most of the attention:

Each query attends only to the last $w$ positions. $q_T$ sees $k_{T-w+1},\dots,k_T$; $q_{T-1}$ sees the $w$ keys ending at $T-1$; and so on. The window slides with the query. $w$ is the window size, a new hyperparameter.

The saving: each query meets only $w$ keys, so the cost is $T\times w$ instead of $T\times T$, linear in $T$. $w$ is usually much smaller than $T$, something like a constant: with $w=1{,}000$ tokens the cost is $T\times1{,}000$ however large $T$ gets.

5 · Seeing further through depth ▶ 28:00

It looks as if attention only covers the last $w$ tokens, but that isn't quite true:

  1. In the top layer, $q_T$ attends to the last $w$ positions, keys $k_{T-w+1},\dots,k_T$.
  2. Each of those keys is a projection of a hidden vector, and that hidden vector came from the layer below, which itself attended to $w$ earlier positions.
  3. The layer below that reaches back $w$ more, and so on. With $l$ layers, information can travel back about $l\times w$ tokens.
  4. That is the limit: tokens further back have no influence. For large enough $T$ the model forgets the distant past.

So you can't use only sliding windows. Many papers propose other forms of sparse attention that don't forget the past; which is best isn't known yet (the course's lecture notes cite some).

Going beyond the lecture. Counted exactly, one layer lets position $t$ see $w$ positions ($t-w+1$ to $t$), each extra layer adds $w-1$ more, so $l$ layers reach $l(w-1)+1$ tokens, which the lecture rounds to $l\cdot w$. Mistral 7B is a well-known open model that used sliding-window attention (with $w=4096$).

6 · Normalising queries and keys ▶ 30:33

One more small detail, about the constant $c$ from part 1. Dividing by $c=\sqrt{d_h}$ assumed each entry of the vectors is on the order of 1. Nothing guarantees that: as training goes on, $q$ and $k$ may grow or shrink.

So some open-source models also normalise the query and key before the inner product. Instead of $q_j k_t^\top/c$ they use

$$\frac{\operatorname{RMSNorm}(q_j)\,\operatorname{RMSNorm}(k_t)^\top}{c},$$

so the inputs to the inner product stay on the same scale in most cases. Again a heuristic, but one people use.

Going beyond the lecture. $\operatorname{RMSNorm}(x)=\gamma\odot x\big/\sqrt{\tfrac1d\sum_i x_i^2+\epsilon}$, with a learned scale $\gamma$. After it, each entry has root-mean-square about 1, which is exactly the "entries on the order of $\pm1$" assumption behind $c=\sqrt{d_h}$. The trick is usually called QK-norm.

Key takeaways

  1. Only the newest query is needed at generation time, but all past keys and values are, so it pays to share keys and values, not queries.
  2. $n_h=\tau n_g$; $\tau$ is tuned. $n_g=1$ is multi-query attention: smallest cache, but it may store too little history, so later models use more KV sets.
  3. Which heads share is irrelevant (it is learned); the grouping is kept simple and static so it compiles well and keeps related work on one GPU.
  4. Sliding-window attention lets each query see the last $w$ keys: cost $T\cdot w$, linear in $T$. Through $l$ layers it reaches about $l\cdot w$ tokens, and forgets everything earlier.
  5. Normalising $q$ and $k$ (e.g. RMSNorm) before the inner product keeps scores on scale when the vectors drift during training.
