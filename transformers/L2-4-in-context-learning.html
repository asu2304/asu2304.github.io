In-Context Learning: Few-Shot and Zero-Shot Prompting

A pretrained language model can pick up a new task from a handful of examples written into its prompt (few-shot), or from a plain description of the task (zero-shot), without a single parameter being updated. That discovery, made famous by GPT-3, replaced the old pipeline of collecting data and fine-tuning a separate model for every customer.

1 · From pretraining to a downstream task ▶ 51:24

With the architecture done, the rest of the lecture is about adapting or using a pretrained model for downstream tasks, such as sentiment analysis or one of your own tasks. Some of this may sound a little out of date, the lecturer warns, but it is still useful in many cases.

2 · In-context learning ▶ 52:01

Suppose the downstream task has examples $(x_1,y_1),\dots,(x_n,y_n)$ and you want the model to predict $y$ from $x$. With in-context learning you literally concatenate the examples into one string, in some format, and append the test input:

Q: x₁ A: y₁ Q: x₂ A: y₂ ⋮ Q: x_test A: ▁

Everything above the last line is the "training" part (in-context training examples); the last line holds $x_\text{test}$, and you hope the model fills in the answer. The lecturer's example:

Q: 2 ~ 3 = ? A: 5 Q: 6 ~ 7 = ? A: 13 Q: 15 ~ 2 = ? A: ▁

Most people answer 17: from two examples you guess that "~" means plus. That is the learning part: you learned what the symbol means. Humans can guess it, not with certainty, and it turns out the models can too.

Try it with a toy "learner" below. It knows a fixed list of candidate operations, keeps those consistent with the examples in the prompt, and predicts with whatever survives. Nothing in it changes except what it reads. (It also shows why the lecturer says "somewhat guess": two examples don't pin the rule down completely.)

Write examples as a ~ b = c, one per line, and a test query. Delete lines to see how fewer examples leave more ambiguity.

The prompt string the model would see:

prediction for the test

Going beyond the lecture: why a toy like this is a fair cartoon. One popular explanation (Xie et al., 2021) views in-context learning as implicit Bayesian inference: pretraining text is generated by many latent "tasks", and the model learns to infer which task a prompt comes from and continue it. The toy does the crisp version of that, keeping only the hypotheses the examples allow. A real model has a soft prior, so it prefers "plus" over exotic rules that also fit.

3 · Few-shot classification ▶ 54:54

Nobody needs a model to learn "plus" this way today. A more realistic use: classify incoming emails as billing, technical, accounting and so on. A few-shot prompt can even hide what the classes mean:

Classify my messages into A, B, C. Message: ⟨message 1⟩ Output: A Message: ⟨message 2⟩ Output: B ⋮ Message: ⟨new message⟩ Output: ▁

Everything up to the blank is prefilled; the model then generates the next token. From the examples it can work out that A seems to mean a billing email and B a technical or customer-service one, and label the new message.

Usually you would not hide the labels: you name them ("billing", "technical"), which makes it easier still. Even then the examples matter, because definitions are subtle. What exactly counts as a billing email? Having seen a few, the model infers "emails with this format or of this type are billing". It is much like teaching a person by examples.

A student remarks that this seems to let you do almost anything. In theory, yes, anything you can teach with examples, and the next part is easier still.

4 · Nothing is updated ▶ 58:14

The parameters are not changed at all. The examples are only given to the model as a string in its context. No training, just prompting.

If you believe the intelligence lives in the parameters, then in-context learning shouldn't improve fundamental capability by much. It mostly teaches style and simple definitions, though some harder things too. But consider biomedical scans where you must classify cancer or not: the lecturer doesn't think a few examples in the prompt would work there. That still needs tuning.

5 · Zero-shot: just describe the task ▶ 59:26

The more extreme version drops the examples. Erase them, and just say "classify messages into billing, technical service, …", describing in text as fully as possible what each label means. That is zero-shot: a task description only (sometimes a long one), then let the model generate the answer.

You can also specify the output format, for example JSON or other structured output: "please generate in this format". That is most people's experience with ChatGPT. Hardly anyone gives few-shot examples these days except in special cases.

6 · Why GPT-3 was a shock ▶ 60:49

Few-shot and zero-shot ability was one of the biggest findings of the GPT-3 paper. It was shocking because the parameters are never updated: people had assumed you must train the model on a new task, at least a little. Instead you just prompt it, and that fundamentally changed how easily these models can be applied in industry.

The old way (say, an insurance company)The new way
Collect lots of domain data and label it; build train and dev setsOne off-the-shelf model for everyone
Start from a checkpoint and train on the domain data, updating parameters; tune hyperparametersEach company writes its own prompt: a task description, sometimes a few examples
Serve a specialised model in that company; repeat the whole process for the next companyLightweight customisation; for agentic tasks some scaffolding, or a complicated workflow

For a workflow, think of the onboarding document a new employee gets describing how to do things: you give that document to the model and it follows the instructions.

7 · How big must the model be? ▶ 63:06

This was once a hot topic: emergent properties. Three or four years ago people observed that these abilities appear only beyond a certain scale of model and data. That is still true, but small models now get them too, by distillation from large models: once a large model shows a capability, you can try to distil it into a small one.

Also, training data is more complicated now. Pretraining used to be just text from the web; now, at some stage of training (maybe not pretraining exactly), there is data that looks like these prompts, so even smaller models get the ability. That leads to the next topic: training for it deliberately.

Key takeaways

  1. In-context learning: put $(x_1,y_1),\dots,(x_n,y_n)$ into the prompt in a fixed format, end with $x_\text{test}$, and let the model complete the answer (e.g. 2 ~ 3 → 5, 6 ~ 7 → 13, so 15 ~ 2 → 17).
  2. Labels can even be hidden (A, B, C); the model infers their meaning, much as a person learns from examples.
  3. No parameter changes: prompting teaches style and simple definitions, but not hard new skills like reading medical scans.
  4. Zero-shot uses only a task description (and maybe an output format); it is how most people use chat models now.
  5. GPT-3 showed this works, replacing per-company data collection and fine-tuning with one model plus prompts; the ability emerged with scale and now reaches small models through distillation and prompt-like training data.
