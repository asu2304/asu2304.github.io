Sequential Decision Making and the MDP

Reinforcement learning is a technique for sequential decision making: choices that change the world, made step after step, and learned from a scalar reward instead of labels. Before any algorithm, we need a model of how decisions move the world. That model is the Markov decision process; this part builds its first three pieces (states, actions, transition dynamics) on a robot walking along a 1-D tape.

1 · Where this lecture sits ▶ 0:05

This lecture is the basics of reinforcement learning (RL). The next one applies RL to large language models, especially to training models that produce long chains of thought.

The running application today is robotics. The reason is pedagogical: with LLMs you would have to absorb two new things at once, the RL setting itself and how to map an LLM onto it. A small robot keeps the setting clean. The destination is one algorithm, policy gradient, which is a core algorithm for both robots and LLMs.

2 · Sequential decision making ▶ 1:08

RL is an algorithmic technique. The problem it attacks is sequential decision making. Unpack the two words:

WordMeaningExample
DecisionYour output is an action that affects the world and has ramifications later. It is not a prediction that is scored and forgotten.Operating a robot; placing an Amazon order.
SequentialNot one round. You decide at every time step, and each decision is followed by more.Telling the robot "go left", "go right", "raise the arm", … at each step.
Put together, greedy fails: what is optimal for the moment may not be optimal for the future. You have to think about downstream consequences.

3 · Exploration versus exploitation ▶ 2:47

A second complication: decisions trade return against risk. Some decisions aren't the best for now but collect information. You arrive in a new city: some restaurant visits are pure exploration. They're not the best choice given what you know, but afterwards you can decide to go there often, or never again.

ExplorationExploitation
GoalUnderstand the world betterDo the best thing given current information
Pay-offLater: you can exploit much better afterwardsNow: more myopic

The lecture flags this early only to set it aside. In today's applications the trade-off is very subtle, and in many cases you simply don't do much explicit exploration: the algorithm explores a little by itself and that's enough. The trade-off is well understood only in some classic settings. So the focus is the sequential part: long-term ramifications.

4 · Learning from reward, not labels ▶ 4:38

The second hallmark: in the classic RL setup there is no or little human supervision, at least not the kind supervised learning has. Often you don't know the optimal actions, not even on your training data. Instead you learn from a reward: usually a scalar that says whether a sequence of actions was good or bad. It evaluates what you did; it doesn't tell you what you should have done.

A consequence: you must collect data yourself, actively. To teach a robot, you generate some actions, let it try them in the real world, and look at the reward. Bad outcome: penalise those actions. If it happens to do well: reinforce them, "keep doing this". It is trial and error, organised as a loop:

collect data (try actions) → score it with the reward → train on it: reinforce the good, penalise the bad → collect again with the updated model
Supervised learningReinforcement learning
SignalLabel: the right answerReward: a score of what you did
DataFixed dataset, givenCollected by the learner's own actions
OutputPredictionActions that change future inputs

5 · The Markov decision process ▶ 7:18

To talk about algorithms we need a way to describe the world and how decisions affect it, now and later. The standard, and very powerful, framework is the Markov decision process (MDP).

Running example. A 1-D tape of cells 1 to 10 with a robot on one cell. You move it left or right, and there's a goal cell to reach. Trivial, but it maps every abstract symbol to something concrete. A bigger mental example: Go, with a 2-D board where each action places a stone.

States $S$ ▶ 9:05

$S$ is the set of states; a state is everything you need to describe the world.

  • Tape: where the robot is, so $S=\{1,\dots,10\}$.
  • Real robot: positions or angles of the arms, joint locations, and often a visual state, e.g. the camera image.
  • Go: the configuration of the whole board. With 361 points, each empty, black or white, there are up to $3^{361}$ configurations.

A student asked whether the state should include information about the robot's surroundings. That's a modelling choice. In theory the state includes everything, but you can't model every detail, so you abstract. People generally don't put, say, a 3-D map of the world in the state; camera images capture some of it.

Actions $A$ ▶ 11:15

$A$ is the set of actions. Tape: $A=\{L,R\}$, try to move left or right. Real robot: how much force to apply at each joint. Go: where to place the stone.

Transition dynamics $P_{sa}$ ▶ 11:58

What happens if you take action $a\in A$ in state $s\in S$? In general the next state is random, so for every pair $(s,a)$ there's a probability distribution over next states:

$$P_{sa}(s') = \Pr\big[\text{arrive at } s' \;\big|\; \text{take action } a \text{ in state } s\big],\qquad \sum_{s'\in S}P_{sa}(s')=1 .$$

So $P_{sa}$ is a vector of dimension $|S|$. If the dynamics are deterministic, $P_{sa}$ puts all its mass on one next state.

Tape example with an inaccurate controller. You say "left" and usually it goes left, but sometimes the robot doesn't move. From cell 7:

$P_{7L}(s')$0 (can't jump two cells)0.90.1 (stays)0 (told left, shouldn't go right)0

The two non-zero entries sum to 1. You must specify such a distribution for every $s$ and $a$. (On the board the lecturer started with $z$ for the next state and switched to $s'$ for consistency; these notes use $s'$ throughout.)

The interaction loop ▶ 16:20

With $S$, $A$ and $P$ you can describe the "game". The subscript on $s$ now indexes time.

  1. Start in an initial state $s_0$.
  2. The algorithm (the agent) chooses an action $a_0\in A$.
  3. Environment step: the action takes effect. Sample the next state from that distribution: $s_1\sim P_{s_0a_0}$. This step is stochastic.
  4. The agent chooses $a_1$, most likely based on $s_1$ (how, is the rest of the lecture).
  5. Environment step again, $s_2\sim P_{s_1a_1}$, and so on: decide, transition, decide, transition.

(On the board, $a_0$ is drawn "from the set of states". That's a slip: actions come from $A$.)

Key takeaways

  1. RL solves sequential decision making: actions change the world, decisions repeat over time, so greedy choices can be wrong.
  2. The exploration–exploitation trade-off is real but subtle; the lecture (and current practice) mostly focuses on the sequential, long-horizon part.
  3. RL learns from a scalar reward, not labels, and collects its own data by trial and error: collect, score, reinforce, repeat.
  4. An MDP starts with states $S$, actions $A$ and transition distributions $P_{sa}$ over next states, with $\sum_{s'}P_{sa}(s')=1$.
  5. Interaction: $s_0$, the agent picks $a_0$, the environment samples $s_1\sim P_{s_0a_0}$, and so on.
